## 1 表

### 1.1 遍历搜索

- 问题：给定边长范围，找出所有直角三角形。
- 造：`ℕ⁺`、`Triangle`、`pyth?`；`for*/list` 版 `right-triangles`；1 到 20 的六组结果；试了 1540 组。
- 造：纯函数可以缓存：`Dictionary`（原 `Dict`，改为全称与 `Substitution` 对齐）、`Bounds`、`cache`、`right-triangles/cached`；三次调用后的 `cache`（点出序对的点）。
- 认：键不重复，值是装着全部答案的列表；把所有边界都算过，`cache` 是一张巨大的表，`right-triangles` 只剩查表（`dictionary->function`）；任何纯函数都可以看作以输入为键的表。
- 名字：表（不加英文，Noah 10/4）、缓存、`dictionary->function`。

### 1.2 关系

- 问题：`Dictionary` 的类型并不要求键唯一；放开限制，把表摊开。
- 造：`rows`：每组答案各配上边界，`(1 20)` 占六行，`(1 4)` 一行也没有。
- 认：行的先后无关，换成集合；用集合的写法描述 $R$，它是笛卡尔积的子集，即关系；纯函数对应的关系；N 元关系、二元关系。
- 造：`rows/5`，同一张表摊成五列，是五元关系；一元关系是子集；零元关系只有 {} 与 {()}。
- 认：谓词把这几种关系连在一起：作为函数是二元关系，让它交出 `#t` 的输入构成 N 元关系；在数学里，这种只回答输入在不在子集里的函数叫**特征函数**（characteristic function）；零参谓词对应两个零元关系。
- 名字：**关系**（relation）、**N 元关系**（N-ary relation）、**二元关系**（binary relation）、**谓词**（predicate）、**特征函数**（characteristic function）。

### 1.3 写不完的表

- 问题：谓词只能检查一行在不在表里，读不出数据；要按键查表。
- 造：自己写 `dict-ref`（`for/first`）与 `dict-ref*`（`for/list`）；`dictionary->function` 与 `table->relation`；在 `rows` 上试。
- 认：`(table->relation rows)` 的类型正是 `right-triangles` 的类型；摊开与收拢来回转换。
- 认：二元关系 $R ⊆ A × B$ 与函数 $A → P(B)$ 一一对应；程序里用列表代替集合，只能表示每个输入的行能有限列出的关系；字典与表来回转换但不是同构（`(1 4)` 这条「已查过但无答案」的记录，PR #151）。
- 认：表可能有无穷多行，程序只需问到哪行算哪行；**惰性**；在程序里表示关系靠函数。
- 名字：**幂集**（power set）$P(B)$、`table->relation`、**惰性**（lazy）。

## 2 循环里的时间线

### 2.1 藏在循环里的局部延续

- 问题（接开头放下的那件事）：循环里没有哪行写着剩余工作，它在哪里，怎样运行了许多次？
- 认：`let*` 与 `for*/list` 并排，每个绑定后面跟着一份剩余工作；区别在可归约式算出一个值还是一个序列。
- 认：与第四篇 `if` 相反，这里剩余工作写了一次运行二十次，一次搜索不止一条时间线。
- 造：三种写法并排：`let` 是 `(k e)`，`for/list` 是 `(map k e*)`，`for*/list` 是 `(append-map k e*)`；抽出 `choose/k`；用它摊开三层循环，结果相同。
- 认：最外层同一个 `k` 运行二十次；参数从左到右求值，一条路走到头再退回：回溯；同一组边界占几行，就有几条走通的时间线。
- 名字：`choose/k`、**回溯**（backtracking）。

### 2.2 擦除延续参数

- 认：摊开后的 `right-triangles` 是 CPS 程序，照第四篇编译器的办法，用 `shift` 在原处取出延续。
- 造：四行改写推导到 `(reset (let ([v (shift k (append-map k p*))]) body))`；起名 `choose`；三层 `reset` 的版本。
- 认：内层两个 `reset` 多余：按第三篇规约规则展开 `(k 3)`，用 `(reset (reset e)) = (reset e)`（回指第四篇化简时同样去掉内层 `reset`）。
- 造：只留一层 `reset` 的 `let*` 版，结果相同。
- 认：主体读起来是一次只有一个值的普通计算，归功于 `choose` 的类型；还剩两处专为搜索写的（包成单行列表或空列表、外层 `reset`）。
- 名字：`choose`。

### 2.3 不确定运算符 amb

- 造：拿掉那两处后想要的伪代码：`between`、`check`。
- 认：`between` 要返回许多次，`check` 要不返回，还要一层收集结果。
- 名字：**不确定计算**（nondeterministic computation）、**不确定运算符**（ambiguous operator）`amb`（McCarthy）、`in-amb`。
- 造：`amb`、`in-amb` 的三个交互例子；`for/amb`；用它们写出 `between`、`check`；`in-amb` 版 `right-triangles`，伪代码一字未改。
- 造：`amb`、`for/amb`、`for*/amb`、`in-amb` 各一行，由 `choose` 与 `reset` 定义；备选包 λ；`(amb)` 一次也不调用 `k`。
- 名字：`for/amb`、`for*/amb`。

## 3 关系成为箭头

### 3.1 二元关系的复合

- 认：`inclusive-range` 与 `right-triangles` 都是交出列表的函数，表示二元关系；`(inclusive-range l h) = (in-amb (between l h))`；有了 `amb`，普通写法的函数能表示每个输入只占有限多行的二元关系。
- 造：`pick-a`、`pick-b`、`pick-c`、`check-right` 用 `∘` 接成 `right-triangle`；四步逐条说明；`(right-triangles l h) = (in-amb (right-triangle (list l h)))`。
- 认：每一步是一张两列的表，表也能复合：首尾相连，遮住中间一列；`(1 2)` 的三行示例表。
- 认：二元关系复合的集合写法；「存在这样的 $y$」由 `amb` 兑现：有了 `amb`，函数的复合就是二元关系的复合；交出集合的函数写法 $(Q ∘ P)(x) = ⋃ \{Q(y) \mid y ∈ P(x)\}$。
- 名字：二元关系的复合。

### 3.2 关系的两种写法

- 问题：`amb` 是借来的，靠 `shift`、`reset` 做出，`between` 也不纯；纯的宿主里二元关系是什么样子？
- 认：回指第二篇借 `call/cc` 的同一个问题与回答（换箭头、配复合）。纯宿主记作 𝒞，添上 `amb` 的宿主记作 ℬ。
- 造：`→𝒞`、`→ℬ`、`inj`、`∘ℬ = ∘`。
- 认：要找的箭头早就有：交出列表的函数，记作 `→ℒ`。
- 造：`list->amb`、`scatter`（ℒ → ℬ）、`gather`（ℬ → ℒ）。
- 认：来回一趟回到原处，两种箭头同构（比的是列表，先后与重复算在内）；`inclusive-range = (gather between)`、`between = (scatter inclusive-range)`。
- 造：借同构把 ℬ 的复合搬过来定义 `∘ℒ`（回指第二篇借道逆否箭头搬运运算律）；两步情形逐行化简，依次经过本篇出现过的四种写法，到 `(append-map g (f x))`；不经 ℬ 直接在 𝒞 里定义 `∘ℒ`（`foldr append-map`；附录与 `code.rkt` 的完整定义支持零支，一元上给出 `(λ (x) (list x))`，与绕道 ℬ 的定义在 0、1、2 支上对齐，见数学库 #76 第 5 条）。
- 认：纯宿主里，二元关系是交出列表的函数，用 `append-map` 接起来，正是上一节取并的式子；`let*` 是 `∘ℬ`，`for*/list` 是 `∘ℒ`，两种箭头各有一种绑定写法。
- 练习：验证 `list->amb` 与 `choose` 是同一个函数。
- 名字：ℬ、ℒ、`→ℬ`、`→ℒ`、`inj`、`∘ℬ`、`∘ℒ`、`list->amb`、`scatter`、`gather`、同构。

## 4 描述关系的语言

### 4.1 想要的写法

- 问题：`amb` 版里 `between` 是取、`pyth?` 是查，用法不同，描述的却是同一类东西；取与查的分别来自函数，不来自关系。1.2 用集合语言写过直角三角形，能不能把集合语言逐字翻译成能运行的程序？
- 造：先写出集合语言的描述 $\{(a, b, c) \mid \text{between}(l, h, a) \wedge \text{between}(a, h, b) \wedge \text{between}(b, h, c) \wedge \text{pyth}(a, b, c)\}$，再逐字翻译为想要的写法：`betweenᵒ`、`pythᵒ`（`function->relation`、`predicate->relation`，上标 ᵒ 照 TRS 命名）与 `run*` 版 `right-triangles`（`run*` 是花括号，`(a b c)` 是竖线左边的形状，下面四行是竖线右边同时成立的条件）。
- 结尾留下两个问题：没有了绑定，`a`、`b`、`c` 是什么？一行 `(betweenᵒ l h a)` 写在那里，又交出了什么？
- 名字：`betweenᵒ`、`pythᵒ`、`function->relation`、`predicate->relation`、`run*`。

### 4.2 未知项、代换与目标

- 问题：回答 4.1 结尾的两个问题，从类型的角度把语言核心逼出来。
- 造与认：
  - **未知项、数据、项与代换**：从 `let*` 的隐式记录表切入。Racket 替 `let*` 记着每个变量的值；`run*` 造出的变量要先当参数交进普通调用，必须是一种数据，叫**未知项**（暂不注英文 `logic variable`，留到 5.2 认出）。不含未知项的值由字面量和序对组成，记作 `Data`；添上未知项 `Var`，合起来叫**项**（term）。未知项的值要自己记一张字典（1.1 缓存用过的 `Dictionary`）。`var`（带 `#:type-name Var`）、`Literal`、`Data`、`Term`、`Substitution`（`(Dictionary Var Term)`）五个定义同块给出。
  - **查表与命名代换**：代换先粗略地只记「未知项 ↦ 值」；写出只查一次表的 `(: value-of (→ Term Substitution Data))`，运行成功与报错两例，再照着「把未知项换成它的值」命名**代换**（substitution）。在 `assq` 按身份找键处演示 `(var 'a)` 打印相同、`eq?` 为 `#f`。
  - **目标**：从 `run*` 两头夹出来——开头是空代换，结尾交出答案列表，每项从一张代换里读出；所以中间那几行条件合起来是「收一张代换，交出零张或多张代换」，即 ℬ 的箭头 `(→ℬ Substitution Substitution)`，叫**目标**（goal），是代换与代换之间的二元关系。（旁注：也可以写成 ℒ 的箭头 `(→ℒ Substitution Substitution)`，复合换 `∘ℒ`，两者之间是 `gather` 与 `scatter`。）
  - **谓词与关系的类型对照**：先看 `pyth?` 与 `pythᵒ`，再一般地并排谓词与关系的类型——`(→ Data ... Boolean)` vs `(→ Term ... Goal)`：谓词（特征函数）收下数据，回答是或否；关系收下项（可含未知项），答不出是或否，只能回答「在哪些取值下成立」，所以交出目标。这门语言里的「关系」是收下项、交出目标的函数；代换之间的二元关系就叫目标。
  - **目标的连接 `∧`**：谓词的条件用 `and` 连，目标的条件怎样连？后一行要读前一行记下的值，所以把目标一行行接起来用的是 `∘ℬ`（3.2 认出 `let*` 是 `∘ℬ`，这里还是 `∘ℬ`），照集合语言里的记号写成 `∧`（按书写顺序倒序交给 `∘ℬ`）。
  - **写出 `run*`**：造未知项、用 `∧` 接目标、从空代换开始运行、`in-amb` 收齐并用 `value-of` 读出。
- 名字：**未知项**、`Data`、**项**（term）、**代换**（substitution）、**目标**（goal）、`value-of`、`∧`。

## 5 合一（microKanren 规模）

- 标题下面不写导语，直接接 4.3 末尾的问题，冲着实现对称的 `(≡ u v)` 去：
  - **顺着查表 `walk`**：把 `x` 等于 `y`、`y` 等于 `5` 记进表里，`value-of` 只查一次读出的是未知项 `y`；值可以是另一个未知项时要顺着查到底，造出 `walk` 并实测。
  - **合一 `unify`**：表里已有 `x ↦ 5` 再来 `x ≡ 6`、或者写成 `6 ≡ x`，直接添一行都会坏；两边先各自 `walk` 到底再对称比对（含序对逐项去对），造出 `unify`。实测三例（两个未知项、`'(a 2)` 对 `'(1 b)` 两边各得一项、`6` 对已绑 `5` 的 `x` 走不通），然后命名**合一**（unification）。代换的一行从「未知项的值」变成「一条等式」。
  - 造出 `(≡ u v)`；升级 `(: value-of (→ Term Substitution Data))` 为顺着查并递归读序对；实测 `(run* (x y) (≡ x y) (≡ y 5))`、`(run* (x y) (≡ x 1) (≡ 2 y))`、`(run* (x) (≡ x 5) (≡ 6 x))`。
  - 回头升级 `function->relation`：最后一列改用 `unify`——没值就添一行，有值就成了核对（`(betweenᵒ 1 5 3)` 与 `(betweenᵒ 1 5 a)` 接 `(betweenᵒ 3 8 a)` 均跑通）。

### 5.1 直接写等式

- 问题：不靠函数和谓词包装，只靠等式能不能写出真正不分输入输出的关系？从 `append` 的定义读出集合/逻辑描述，要逐字翻译成三元关系 `(appendᵒ l t out)`，还缺两样东西：
  - **「或者」`∨` 与两个单位 `⊤`、`⊥`**：目标里挑一个成立就是 `amb`，造出 `∨`（表上是把两张表并起来；旁注：ℒ 箭头里是接起几张代换列表）。问 `∧` 与 `∨` 一个目标也不给时交出什么，拿记着 `a ↦ 1` 的代换实测，认出**恒等关系**与**空关系**，命名 `⊤` 与 `⊥`（合取与析取的**单位**；并回扣 1.2 节的两个零元关系 `{()}` 与 `{}`）。
  - **局部未知项 `∃`**：关系定义里需要造只属于内部的未知项，写出宏 `(∃ (x ...) g ...)`（收到代换时才造未知项，递归的关系才停得下来）。
- 造：逐字写出 `appendᵒ`（全用 `∨`、`∧`、`∃`、`≡`）。
- 认：正着问与 `append` 一样；倒着问 `(run* (x y) (appendᵒ x y '(1 2 3)))`，四种拆法全找到。高潮单独成段：「定义 `appendᵒ` 的时候，没有哪一行写过『拆』：每一行都是等式，没有哪个位置是输入，哪个是输出。这是关系不分输入输出的样子。」（不加限定。）
- 名字：**合一**（unification）、`walk`、`unify`、`≡`、`∨`、**恒等关系**（identity relation）、**空关系**（empty relation）、**单位**（unit）、`⊤`、`⊥`、`∃`。

### 5.2 读出还不知道的项

- 问题：等式两边都可以不知道，`(run* (x y) (≡ x y))` 用 `value-of` 报错。可它不是无解，它说的是两个位置相等、取几都行。
- 造：`walk*` 与 `(: reify (→ Term Data))`（给换不动的未知项依次起名 `_.0`、`_.1`，整个查询元组放在一张列表里一起读出，共用一套名字；沿用 miniKanren 的显示惯例，数学库 #76 第 4 条），写出第二版 `run*`。
- 认：实测 `(run* (x y) (≡ x y))` 得 `((_.0 _.0))`、`(run* (x y) ⊤)` 得 `((_.0 _.1))`、`(run* (x y) (appendᵒ '(1) x y))` 得 `((_.0 (1 . _.0)))`。在这里首次点明：**一张代换不是一组答案**，它说的是未知项之间要满足的关系；一组带名字的答案代表许多行（甚至无穷多行）。
- 认（收束整门语言的来历，原 7.2 合并至此）：只有等式、合取、析取、存在和两个单位，这不到一百行的小语言骨架就是 **microKanren**——**逻辑式编程**（logic programming）语言 **miniKanren** 的极小内核，未知项在那里叫**逻辑变量**（logic variable），`≡`、`∧`、`∨`、`∃`、`⊤`、`⊥` 常写作 `==`、`conj`、`disj`、`fresh`、`succeed`、`fail`。常见实现用流回溯，要手写合取与析取；这里用 `amb` 回溯，`∧` 就是 ℬ 的复合，`∨` 就是 `amb`，剩下主要只写合一。
- 旁注：occurs 检查（`(≡ x (cons 1 x))` 应当无解，附录代码带这一步）；与常见实现的差别（未知项按身份区分不编号、合取是直接复合、推迟计算与取答案方式不同，交出顺序可能不同）；`_.0` 显示名惯例说明（若项里本身含符号 `'_.0`，读出后会撞名）。
- 名字：`walk*`、`reify`、**逻辑式编程**（logic programming）、**逻辑变量**（logic variable）、microKanren、miniKanren。

## 6 关系的世界 ℛ

- 导语只放一个问题：前面四步都是带 `amb` 的函数，用 `∘` 就接成了 `right-triangle`。现在有了一门直接写关系的语言，关系交出的是目标，`∘` 接不上，两个关系怎样接起来？记号 ℛ 推迟到 6.3 三种写法并排时再起名。

### 6.1 在关系语言里复合

- **先用谓词（特征函数）试着定义二元关系的复合，失败**：照 3.1 集合复合的定义 `{(x, z) | ∃y. P(x, y) ∧ Q(y, z)}` 去写两个二元谓词 `P?`、`Q?` 的复合，卡死在「存在这样的 `y`」——除非把 `y` 所在集合的全部元素列出来逐个检查（且集合有限），否则特征函数定义不出复合。
- **转到关系语言**：集合语言里的 `∃y. P(x, y) ∧ Q(y, z)` 逐字翻译就是 `(∃ (y) (P x y) (Q y z))`——未知项 `y` 替我们占住中间那一列，不需要穷举全集；`run*` 只读出 `x` 与 `z`，中间一列被遮住。顺口点明：在代换层 `∧` 是目标的复合 `∘ℬ`，在答案表上 `∧` 是按共有的列拼起来。
- **零个关系的复合**：试着把恒等函数 `id`（与第二章及 STYLE 统一）搬成关系 `(function->relation id)` 接在只看第二个位置的 `P` 右边，问 `(run* (q) ...)` 报错；换成等式 `(define (idᵒ x y) (≡ x y))`，答案与 `P` 自己一致。在关系语言里，恒等关系是相等。
- **写出 `∘ᵒ`**：用四分支 `case-λ` 定义，二元复合单占一行，零元交出 `idᵒ`，一元交出 `P`（免去多余包装），多元递归复合：
  `(case-λ [() idᵒ] [(P) P] [(Q P) (λ (x z) (∃ (y) (P x y) (Q y z)))] [(Q . P*) (∘ᵒ Q (apply ∘ᵒ P*))])`。
- 名字：`idᵒ`、`∘ᵒ`。

### 6.2 四步搬过来

- 问题：`right-triangle` 的四步是带 `amb` 的函数，用 `function->relation` 各搬成一个关系再用 `∘ᵒ` 接起来，说的还是同一张表吗？
- 造：`pick-aᵒ`、`pick-bᵒ`、`pick-cᵒ`、`check-rightᵒ`、`right-triangleᵒ`，运行得同样六组。
- 认：三种复合与绑定写法并排（在 3.2 末尾两行下添第三行）：
  - `(let*      ([y (f x)] [z (g y)]) z)  =  ((∘ℬ g f) x)`
  - `(for*/list ([y (f x)] [z (g y)]) z)  =  ((∘ℒ g f) x)`
  - `(∃ (y) (P x y) (Q y z))              =  ((∘ᵒ Q P) x z)`
- 认：倒着问 `(run* (b) (right-triangleᵒ b '(3 4 5)))` 仍报错（函数搬来的关系仍要求输入已知；因 `∘ᵒ` 有 `[(P) P]`，报错直接是 `b 的值还不知道`）。

### 6.3 几个世界之间

- 写成散文，不列条目。在这里正式给关系语言所在的世界起名 ℛ。
- ℬ 与 ℒ 用 `gather` 与 `scatter` 来回搬（条件进旁注）；ℬ 到 ℛ 是 `function->relation`（6.2 刚搬过）；ℛ 往回搬一般搬不动。
- 往回搬不动的现象改用**全关系 `(define (U x y) ⊤)`**（数学库 #76 第 6 条）：固定任意一个输入 `x`，`(run* (y) (U x y))` 得 `((_.0))`，所有项都是答案——同一个输入对着无穷多行，无论以哪一列为输入都写不成有限列表，也走不完 ℬ 的箭头。
- 名字：ℛ。

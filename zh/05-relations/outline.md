## 1 表

### 1.1 遍历搜索

- 问题：给定边长范围，找出所有直角三角形。
- 造：`ℕ⁺`、`Triangle`、`pyth?`；`for*/list` 版 `right-triangles`；1 到 20 的六组结果；试了 1540 组。
- 造：纯函数可以缓存：`Dict`、`Bounds`、`cache`、`right-triangles/cached`；三次调用后的 `cache`（点出序对的点）。
- 认：键不重复，值是装着全部答案的列表；把所有边界都算过，`cache` 是一张巨大的表，`right-triangles` 只剩查表（`dictionary->function`）；任何纯函数都可以看作以输入为键的表。
- 名字：表（不加英文，Noah 10/4）、缓存、`dictionary->function`。

### 1.2 关系

- 问题：`Dict` 的类型并不要求键唯一；放开限制，把表摊开。
- 造：`rows`：每组答案各配上边界，`(1 20)` 占六行，`(1 4)` 一行也没有。
- 认：行的先后无关，换成集合；用集合的写法描述 $R$，它是笛卡尔积的子集，即关系；纯函数对应的关系；N 元关系、二元关系。
- 造：`rows/5`，同一张表摊成五列，是五元关系；一元关系是子集；零元关系只有 {} 与 {()}。
- 认：谓词把这几种关系连在一起：作为函数是二元关系，让它交出 `#t` 的输入构成 N 元关系；零参谓词对应两个零元关系。
- 名字：**关系**（relation）、**N 元关系**（N-ary relation）、**二元关系**（binary relation）、**谓词**（predicate）。

### 1.3 写不完的表

- 问题：谓词只能检查一行在不在表里，读不出数据；要按键查表。
- 造：自己写 `dict-ref`（`for/first`）与 `dict-ref*`（`for/list`）；`dictionary->function` 与 `table->relation`；在 `rows` 上试。
- 认：`(table->relation rows)` 的类型正是 `right-triangles` 的类型；摊开与收拢来回转换。
- 认：二元关系 $R ⊆ A × B$ 与函数 $A → P(B)$ 一一对应；程序里用列表代替集合，只能表示每个输入的行能有限列出的关系；字典与表来回转换但不是同构（空列表的键）。
- 认：表可能有无穷多行，程序只需问到哪行算哪行；**惰性**；在程序里表示关系靠函数。
- 名字：**幂集**（power set）$P(B)$、`table->relation`、**惰性**（lazy）。

## 2 循环里的时间线

### 2.1 藏在循环里的局部延续

- 问题（接开头放下的那件事）：循环里没有哪行写着剩余工作，它在哪里，怎样运行了许多次？
- 认：`let*` 与 `for*/list` 并排，每个绑定后面跟着一份剩余工作；区别在可归约式算出一个值还是一个序列。
- 认：与第四篇 `if` 相反，这里剩余工作写了一次运行二十次，一次搜索不止一条时间线。
- 造：三种写法并排：`let` 是 `(k e)`，`for/list` 是 `(map k e*)`，`for*/list` 是 `(append-map k e*)`；抽出 `choose/k`；用它摊开三层循环，结果相同。
- 认：最外层同一个 `k` 运行二十次；参数从左到右求值，一条路走到头再退回：回溯；同一组边界占几行，就有几条走通的时间线。
- 名字：`choose/k`、**回溯**（backtracking）。

### 2.2 擦除延续参数

- 认：摊开后的 `right-triangles` 是 CPS 程序，照第四篇编译器的办法，用 `shift` 在原处取出延续。
- 造：四行改写推导到 `(reset (let ([v (shift k (append-map k p*))]) body))`；起名 `choose`；三层 `reset` 的版本。
- 认：内层两个 `reset` 多余：按第三篇规约规则展开 `(k 3)`，用 `(reset (reset e)) = (reset e)`（回指第四篇化简时同样去掉内层 `reset`）。
- 造：只留一层 `reset` 的 `let*` 版，结果相同。
- 认：主体读起来是一次只有一个值的普通计算，归功于 `choose` 的类型；还剩两处专为搜索写的（包成单行列表或空列表、外层 `reset`）。
- 名字：`choose`。

### 2.3 不确定运算符 amb

- 造：拿掉那两处后想要的伪代码：`between`、`check`。
- 认：`between` 要返回许多次，`check` 要不返回，还要一层收集结果。
- 名字：**不确定计算**（nondeterministic computation）、**不确定运算符**（ambiguous operator）`amb`（McCarthy）、`in-amb`。
- 造：`amb`、`in-amb` 的三个交互例子；`for/amb`；用它们写出 `between`、`check`；`in-amb` 版 `right-triangles`，伪代码一字未改。
- 造：`amb`、`for/amb`、`for*/amb`、`in-amb` 各一行，由 `choose` 与 `reset` 定义；备选包 λ；`(amb)` 一次也不调用 `k`。
- 名字：`for/amb`、`for*/amb`。

## 3 关系成为箭头

### 3.1 二元关系的复合

- 认：`inclusive-range` 与 `right-triangles` 都是交出列表的函数，表示二元关系；`(inclusive-range l h) = (in-amb (between l h))`；有了 `amb`，普通写法的函数能表示每个输入只占有限多行的二元关系。
- 造：`pick-a`、`pick-b`、`pick-c`、`check-right` 用 `∘` 接成 `right-triangle`；四步逐条说明；`(right-triangles l h) = (in-amb (right-triangle (list l h)))`。
- 认：每一步是一张两列的表，表也能复合：首尾相连，遮住中间一列；`(1 2)` 的三行示例表。
- 认：二元关系复合的集合写法；「存在这样的 $y$」由 `amb` 兑现：有了 `amb`，函数的复合就是二元关系的复合；交出集合的函数写法 $(Q ∘ P)(x) = ⋃ \{Q(y) \mid y ∈ P(x)\}$。
- 名字：二元关系的复合。

### 3.2 关系的两种写法

- 问题：`amb` 是借来的，靠 `shift`、`reset` 做出，`between` 也不纯；纯的宿主里二元关系是什么样子？
- 认：回指第二篇借 `call/cc` 的同一个问题与回答（换箭头、配复合）。纯宿主记作 𝒞，添上 `amb` 的宿主记作 ℬ。
- 造：`→𝒞`、`→ℬ`、`inj`、`∘ℬ = ∘`。
- 认：要找的箭头早就有：交出列表的函数，记作 `→ℒ`。
- 造：`list->amb`、`scatter`（ℒ → ℬ）、`gather`（ℬ → ℒ）。
- 认：来回一趟回到原处，两种箭头同构（比的是列表，先后与重复算在内）；`inclusive-range = (gather between)`、`between = (scatter inclusive-range)`。
- 造：借同构把 ℬ 的复合搬过来定义 `∘ℒ`（回指第二篇借道逆否箭头搬运运算律）；两步情形逐行化简，依次经过本篇出现过的四种写法，到 `(append-map g (f x))`；不经 ℬ 直接在 𝒞 里定义 `∘ℒ`（`foldr append-map`，参数表是示意写法）。
- 认：纯宿主里，二元关系是交出列表的函数，用 `append-map` 接起来，正是上一节取并的式子；`let*` 是 `∘ℬ`，`for*/list` 是 `∘ℒ`，两种箭头各有一种绑定写法。
- 练习：验证 `list->amb` 与 `choose` 是同一个函数。
- 名字：ℬ、ℒ、`→ℬ`、`→ℒ`、`inj`、`∘ℬ`、`∘ℒ`、`list->amb`、`scatter`、`gather`、同构。

> **Noah 11/6 的后半思路**（他的原话整理，下面各节照此改写）：下半部讲用 `amb` 实现 microKanren，叙事线索是把谓词和函数都转换成关系。伪代码说的是四个关系同时成立，要交出满足它们的全部未知项，所以实现的核心落在未知项上：它们之间要满足的关系就是 Subst（环境表，表本身就是关系，也扣题）。每个关系交出一个 Goal：在某个 Subst 的基础上添上一些约束，得到所有可能的新 Subst，所以 Goal 也是二元关系。conj 是二元关系的复合；同一个笛卡尔积有许多子集，取并集就是 disj。这门语言里有几层关系：Subst、Goal、用户定义的关系 `(→ Term ... ### 4.2 未知项、代换与目标（计划第 2 步）

- 问题：回答 4.1 结尾的两个问题。
- 造：
  - **未知项**按身份区分，不按打印出来的名字；
  - **代换**记着已经建立的未知项与项之间的等式，是 1.1 那种键不重复的字典（键是未知项，值是项，可能是另一个未知项或含未知项的结构）；
  - 一行关系交出一个**目标**：收到一个代换，交出零个或多个添了约束的代换。
- 认：代换是一张表，记着未知项之间要满足的关系（Noah 11/6 的读法，Astra 11/6 核过可以保留）。它的意思是所有满足这些等式的赋值；`x ↦ y` 只说两者相等，没有确定 `x` 的值。（Claude 提的「代换是答案表的一行」不采用：它表达不了 `(_.0 _.0)` 与 `(_.0 _.1)` 的差别，Astra 11/6 第 7 条。）
- 认：目标是代换之间的二元关系，在 ℬ 里类型是 `(→ℬ Subst Subst)`。代换限于无环、键不重复的合法状态；`fresh` 分配新的未知项，所以说「同一个代换」时按新鲜变量改名后比较。
  - 合取 `conj` 是二元关系的复合，即 `∘ℬ`（3.1 的复合在这里兑现）。理由是目标收下一个代换、交出一个代换，前一个的输出接后一个的输入；不是因为两者住在同一个积里（同一个积里的子集也能取交）；
  - 析取 `disj` 按集合看是两个子集的并，在 ℬ 里就是 `amb`；按列表看保留先后与重复。在目标这一层实现析取是本内核的选择；
  - `succeed` 是恒等关系，合取的单位；`fail` 是空关系，析取的单位，即 `(amb)`。
- 认：三层要分清，正文叫法不能混：
  - 程序的三种类型：用户定义的关系 `(→ Term ... Goal)` 是参数化的目标构造器，描述项之间的关系；目标变换代换；代换是未知项到项的有限绑定表。
  - 观察的三层（Astra 10/4、11/6）：原始代换、读出的符号答案、答案表示的数学解集。不同的原始代换可以读出同一个答案，一个符号答案又可能代表许多组解。
- 认：两个库对应 3.2 的两个世界，只在前半的条件下（有限终止、纯搜索、深度优先、按答案列表观察）：`demo.rkt` 的目标 `(→ Subst Subst)` 带 `amb`，是 ℬ 的箭头；miniKanren-typed 的目标 `(→ Subst (Streamof Subst))` 在流全部展开、用 `conde`（`bind`/`mplus`，不用 `condi`）时对应 ℒ 的箭头。正文用列表，不引入流；加入无限流与交错就超出 `gather`/`scatter` 可逆的范围（Astra 11/6 第 8 条）。
- 名字：**未知项**、**代换**（*substitution*；原称「环境」，Noah 11/6 用 Subst，叫法写时再定）、**目标**（*goal*）、`succeed`、`fail`、`conj`、`disj`。

### 4.3 跑起来

- 造：`function->relation`、`predicate->relation` 把函数、谓词搬成关系；`run*`。4.1 的程序原样运行。
  - `function->relation` 要求输入位置已确定（`walk*` 后检查），输出位置可以未知；`predicate->relation` 要求全部参数已确定。
  - `run*` 收多个查询未知项 `(a b c)`（`demo.rkt` 只收一个）：整个查询元组一起 `walk*`、`reify`，不能逐项各自 `reify`，否则共享的未知项会丢（Astra 11/6）。
- 认：`run*` 不是关系，是转换，分三步：把目标用在空的代换上；`in-amb` 收集成功的代换（即 3.2 的 `gather`）；读出查询项。按解集看，局部未知项不出现在答案里，对应 ∃ 与投影，在表上是遮住其余的列，投影后相同的行归并。实际交出的列表可能重复，读出的是符号答案；`fresh` 引入的未知项在原始代换里通常仍有绑定，「遮列」发生在读出这一步。
- 实现注意：本章的 `in-amb` 是 `(reset (list ...))` 配 `append-map`，先收完再交出。`run*` 这样写没问题；「只要第一组」一类的实验要另说用哪种 `in-amb`。

## 5 合一（Noah 11/5 定：加入合一，做到 microKanren 的规模）

- 5.1 直接写等式：`==`；`fresh`（收到代换时才造未知项，递归的关系才停得下来）；`appendᵒ` 正着问、倒着问（四种拆法）。
- 5.2 读出还不知道的项：`(run* (x y) (== x y))` 用 `value-of` 报错 → `walk*`、`reify`，`run*` 第二版整个元组一起读出；`(_.0 _.0)` 与 `(_.0 _.1)` 的差别兑现代换的读法；occurs 检查放进旁注与附录。
- 造：`unify`：`walk`、`ext-s`、occurs 检查；`==`。照 `demo.rkt`：代换用关联列表，失败是 `(amb)`；`reify` 读出还没确定的未知项。
- 认：用 `==` 写成的关系在逻辑上不指定输入输出方向，可以提出反向查询，如 `appendᵒ` 拆列表，本例算出四组。不说「用了 `==` 就任意方向都跑得完」：含递归、合取、析取的关系，换查询方向或子句顺序可能改变终止性与能找到的答案。`betweenᵒ`、`pythᵒ` 这类由函数、谓词搬来的关系仍要求参数已知。
- 认：二元关系 `(λ (x y) (== x y))` 表示相等关系，即对角线；一行 `(== t1 t2)` 则筛选出使两项相等的赋值，如 `(== x 1)` 说 x = 1。`==` 在代换上不是恒等，它可能添上绑定。
- 认：occurs 检查是本章的选择（项限于有限无环的树），`demo.rkt` 有，原始 microKanren 没有。
- 名字：**合一**（*unification*）。

## 6 关系的世界 ℛ（计划第 3 步；Noah 11/6 定保留：这正是他理解里第一部的主线）

- 认：关系语言才是真正基于关系的世界，二元关系在这里定义最合适；`amb` 版与列表版都是对关系的模拟（Noah 10/5 18:35）。
- 造：复合 `∘ᵒ`。集合写法里的「存在这样的 y」就是 `fresh`，在表上就是遮住中间一列。
- ℛ 的箭头与「相同」（Astra 11/6 第 12 条）：项上可定义的二元关系，按解集比较。这样得到关系世界的一部分，复合封闭、含相等关系。它可能有无穷多行对应同一个输入（例如 `(λ (x y) succeed)`），所以不是前半那种「每个输入只有有限多行」的关系；程序本身另有先后、重复、停不停这些观察。
- 认：`(fresh (y) (P x y) (Q y z))` 就是 ∃y.(P(x, y) ∧ Q(y, z))，所以 `∘ᵒ` 是关系的复合。结合律在解集上成立，不在原始代换或答案列表上。
- 造：单位 `(define (idᵒ x y) (== x y))`。不用 `(function->relation values)`：它要求输入已知，只在正向查询里是单位（反例：`(run* (q) ((∘ᵒ P (function->relation values)) q 1))`，其中 `(define (P x y) (== y 1))`）。
- 造：3.1 的四步用 `function->relation` 搬到 ℛ，用 `∘ᵒ` 接起来，输入已确定时给出同样的答案。
- 认：几个世界之间的图（Astra 11/6 第 15 条），不画成三边互逆：
  - ℬ ↔ ℒ：`gather`/`scatter`，在前半的条件下互逆；
  - ℒ 与 ℬ 都可以忘掉先后与重复，落到关系上，三角形交换；
  - ℬ → ℛ：`function->relation`，只在输入已确定的查询里核对答案；ℒ → ℛ 先 `scatter` 再包装；
  - ℛ 的程序 → 关系：读出查询项、解释剩下的未知项、忘掉先后与重复。两条包装路线落到同一个关系。
  - ℛ → ℒ 或 ℛ → ℬ 没有一般的反向搬运：带未知项的符号答案不能充当全部确定元组的列表。
  - 和第二章 𝒞、𝒰、𝒦 那张图的对照，写的时候再看哪些边可以并排（**未定**）。
- 旁注：这门语言建在 `amb` 上；由函数、谓词搬来的关系仍要求参数已知。
- 回扣绑定的写法（Noah 10/6）：3.2 末尾两行之下添第三行 `(fresh (y) (P x y) (Q y z))  =  ((∘ᵒ Q P) x z)`。

## 7 与逻辑的对应（计划第 4 步）

- 从 `∘ᵒ`（或 4.3 的 `run*`）读出：存在对 `fresh`，并且对合取，属于对关系的应用；再补析取、相等与两个单位。
- 对照表合成三列：Noah 知乎回答的 miniKanren 与构造性逻辑两列，加上表这一列（Claude 建议）。表这一列说的是解集，不是代换：在解集上合取是按共有的列拼接，在代换上才是复合（Astra 10/4 第 7 条）。这一列就是关系代数的正片段（选择、投影、自然连接、并）；遇到无限的项域、带未知项的答案与递归，要和有限的、写得出来的表区别开（Astra 11/6 第 16 条）。

| miniKanren | 逻辑 | 表 |
| --- | --- | --- |
| `succeed` | ⊤ | 零元关系 {()} |
| `fail` | ⊥ | 零元关系 {} |
| `(== t1 t2)` | t1 ≡ t2 | 使两项相等的赋值（二元的 `(λ (x y) (== x y))` 是对角线） |
| `(conde [g1] [g2])` | g1 ∨ g2 | 两个子集取并（列不同时先扩到共同的列） |
| `(fresh () g1 g2)` | g1 ∧ g2 | 按共有的列拼接（没有共有的列时是笛卡尔积） |
| `(fresh (x) (P x))` | ∃x. P(x) | 遮住一列 |
| `(run* (x) (P x))` | {x ∣ P(x)} | 符号答案的列表；全部确定、跑完并去重以后才是整张表 |

- 认：零元关系两层要分开：`succeed`、`fail` 在接口上已经是目标，没有「收零个项再交出目标」的那一层调用；作为不含未知项的公式，它们表示 1.2 的 {()} 与 {}（Noah 11/6：零元关系就是 succeed、fail）；落到实现，是目标这一层的恒等关系与空关系。
- 认：这是一个 microKanren 风格的小内核：`amb` 承担分支与回溯，普通的复合串起目标，省掉了显式的 `mplus`/`bind`。和原始 microKanren 的差别还有新鲜变量的管理（按对象身份，不用计数器）、延迟、答案的取用方式、occurs 检查；不说「差的只是交错」（Astra 11/6 第 17 条）。
- 名字：microKanren、miniKanren。是否引入 `conde`（`disj` 的语法）写时再定。

标题：标签成为逻辑之时：揭开 call/cc 的神秘面纱

主线：从一等标签出发，经 `cc` 推出 `call/cc`，三者互相定义；再把它们的类型读成命题，认出经典逻辑，分界线落在「消耗否定」与「凭空造出否定」之间；最后把排中律反过来代入具体类型，得到阴阳谜题与 $¬¬q$。

## 0. 开头

- 接作者此前的知乎回答（`call/cc` 与 `goto`、`label`、阴阳谜题）；本文把那个思想实验完整走一遍。
- `control-context` 包；注意框：代码针对最新版 Racket。

## 1. 引言

- 问题：`call/cc` 常被说成「美化的 goto」，能否照字面检验？标签成了值，离 `call/cc` 还有多远？
- 名字：`call/cc`、一等标签。

## 2. 一等标签

- 造：`goto`、`label` 的类型；空类型 $⊥$ 写成 `(∪)`。
- 注意框：`#lang typed/racket/no-check`，类型是设计文档，不经检查。
- 名字：$⊥$、`Label`、`goto`、`label`。

### 2.1 循环

- 造：用标签和 `set!` 写计数循环。

### 2.2 提前返回

- 造：`mul` 第一版：返回标签 `ret`，遇零跳到末尾；`first?` 区分首次进入与跳回。

### 2.3 标签的问题

- 认：两个例子都靠 `set!` 在跳转之间传信息；`first?` 与乘法无关。

## 3. 从标签到延续：`cc` 操作符

- 问题：`goto` 不带载荷；要向跳转目标送一个值。
- 造：`cc`，返回 $p ∪ (p → ⊥)$；内部仍用 `label`、`goto`、`set!`，但封装起来。
- 注意框：多值处理（`v*`、`apply values`），类型标注省略多值。
- 名字：延续、`cc`。

### 3.1 再写 `mul`

- 造：`mul` 第二版，用 `(cc)` 与 `real?` 分支；两条路径汇入同一个延续，不需要可变状态与标志。

## 4. 消除分支：`call/cc`

- 问题：`cc` 要求调用者分支；能否把分支藏进操作符？
- 造：`call/cc` 由 `cc` 定义，`list?` 区分两种情形；`let/cc` 语法糖。
- 练习：用 `let/cc` 定义 `call/cc`。
- 名字：`call/cc`、`let/cc`。

### 4.1 更一般的延续类型

- 造：`absurd`（`(case-λ)`），$⊥ → q$。
- 认：`(compose absurd k)` 与 `k` 行为相同，延续可视为 $p → q$；`call/cc` 得到 $((p → q) → p) → p$；提到 Haskell 的 `callCC`。本文仍用 $p → ⊥$ 版。
- 名字：`absurd`。

### 4.2 那条看不见的延续

- 认：`(call/cc proc)` 与 `(call/cc (λ (k) (k (proc k))))` 相同（`proc` 在尾位置，延续就是 `k`）；`proc` 可读作 $(p → ⊥) → ⊥$，`call/cc` 读作 $((p → ⊥) → ⊥) → p$。
- （第二篇「三种写法」回指这一节的论证。）

## 5. 从 `call/cc` 定义标签

- 造：`(define-type Label (→ Label ⊥))`、`(goto l) = (l l)`、`(label) = (call/cc goto)`；反过来由标签定义 `call/cc`，再由它定义 `cc`。
- 认：三种表述表达能力等价。
- 名字：递归类型 `Label`。

## 6. 比较

- 表：一等标签、`cc`、`call/cc` 在类型、可变状态、手动分支三方面的取舍。
- 认：力量来自同一步：跳转目标成为值；其余是易用性的取舍。

## 7. 深层的逻辑

- 问题：签名里只剩 $→$、$⊥$、$∪$；把五个签名摆在一起，像五条定律（排中律、Clavius 律、Peirce 律、DNE、爆炸原理），只是字面相像吗？
- 表：类型与「像什么」。

### 7.1 从 $⊥$ 出发

- 认：$⊥$ 对应假；$¬⊥$ 有值（恒等、`absurd`）；只用 λ 写不出非空类型的 $p → ⊥$，延续都是运行时捕获的。
- 造：`(define-type (¬ p) (→ p ⊥))`。
- 名字：否定 $¬$。

### 7.2 从类型到逻辑

- 认：$→$、`values`（$×$）、$∪$ 对应蕴含、合取、析取；单位元 $⊤$（`(Values)`）与 $⊥$；Values 嵌套只是示意（一句说明）。
- 认：Curry-Howard 对应；签名改写为 $¬$、$∨$；$\text{Label} = ¬\text{Label}$；表格第二列不再说「像」，除爆炸原理外都只在经典逻辑中成立。
- 名字：蕴含、合取、析取、$⊤$、Curry-Howard 对应、DNE。

### 7.3 对应关系在哪里失效

- 认：三种失效：`(loop)` 有类型 $¬⊤$；`exit` 让任何 $¬p$ 非空；$\text{Label} = ¬\text{Label}$ 是说谎者悖论，正性条件（与严格正性）禁止它；环形振荡器。
- 认：对应关系作为结构性指引。
- 名字：说谎者悖论、正性。

### 7.4 分水岭

- 问题：`cc`、`call/cc` 到底添加了什么？
- 造：`apply-cont`（矛盾律，就是函数调用）；DNI 是参数顺序不同的同一操作（`(curryr apply-cont)`）。
- 认：排中律是 `cc`，DNE 是 `call/cc`；二乘二的表：消耗否定是构造性的，凭空造出否定是经典的。
- 练习：实质条件 `material->procedure` / `procedure->material`，哪个方向要 `cc`。
- 名字：矛盾律、`apply-cont`、DNI、直觉主义逻辑、构造性。
- （「数一数 k」的基础说明迁入时，接在这里：矛盾律是相邻两层相遇，DNI 加两层，DNE 减两层；待改。）

## 8. 代入排中律

- 问题：对应关系反过来用：把具体类型代入定律，得到新定理。代入经典定律可能得到 λ 写不出的操作符，先从命题形状读出它做什么。选排中律（`cc` 的类型）。

### 8.1 代入 $\text{Label}$

- 认：$\text{Label} ∨ ¬\text{Label} = \text{Label}$，否定的不动点；`goto` 本身就是 `Label`；`((label) (label))`：跳转目标与跳转指令是同一种东西。
- 名字：否定的不动点。

#### 8.1.1 阴阳谜题

- 造：用 `(label)` 写出阴阳谜题，`@` 用 `displayln`、`*` 用 `display`，输出成阶梯。
- 问题：多出来的那个 `*` 记在哪里？
- 造（追踪谜题）：插桩版 `cc`、`apply-cont`（延续成了 `cons` 对，借 Racket 自带的 `let/cc`），追踪输出。
- 认（读矩阵）：追踪排成矩阵，每行对应原谜题的一行；三条规律；委托链每经过 `k0` 多一环。
- 造（用函数重写）：照三条规律把延续写成函数 `k0`、`kn+1`，输出相同。
- 认：没有 `label`、`cc`、`set!`；延续成了显式参数，这种写法是 CPS，改写是 CPS 变换；原谜题是这组互递归调用，延续由运行时捕获；谜题是说谎者悖论运行起来的样子。
- 名字：阴阳谜题、延续传递风格（CPS）、CPS 变换、互递归调用。

### 8.2 代入 $¬q$

- 问题：不要求类型否定自己，只要求它是另一个类型的否定：$¬q ∨ ¬¬q$。`cc` 直接交出 $¬¬q$ 意味着什么？

#### 8.2.1 程序的类型

- 造：用 `call/cc` 模拟 `exit`，`(call/cc (λ (exit) (exit …)))`；外层的 `exit` 不能省。
- 认：`(λ (exit) …)` 的类型是 $¬¬\text{Byte}$；OS 运行程序就是一次 DNE（C 规定从 `main` 返回等于调用 `exit`）；程序是一个 $¬¬q$，等一条来自未来的延续。
- 引出：程序是推迟计算，另一种常见形式是 thunk。

#### 8.2.2 Thunk（待删减）

- 造：thunk 读当前的 `b`；`parameterize` 例子：thunk 运行在调用点的求值上下文里。
- 认：thunk 记得定义处的变量绑定，求值上下文由调用点决定；反过来（冻结上下文、变量读当前值）thunk 做不到。
- 名字：thunk、求值上下文。

#### 8.2.3 冻结上下文（待删减）

- 认：`(cc)` 在 $¬q ∨ ¬¬q$ 下交出的是 $¬¬q$；跳回捕获点就回到那里的求值上下文。
- 造：`(define-type (¬¬ q) …)`；`wait/fc`（$¬¬q → ¬¬q$，又用回 `first?` 与 `set!`），放宽为 $(¬q → q) → ¬¬q$。
- 表：`call/cc` 与 `wait/fc`：当前延续与未来延续。
- 造：thunk 例子换成 `wait/fc`，`parameterize` 不可见，`b` 读当前值。
- 认：恢复动态范围、继承变量状态；与可执行文件的类比（`proc` 是源代码，`wait/fc` 是构建，$¬¬q$ 是可执行文件）；值、thunk、$¬¬q$ 的对照表。
- 名字：`¬¬`、`wait/fc`、未来延续、动态范围。

#### 8.2.4 组合冻结上下文（待删减）

- 造：`dynamic-wind` 介绍；W1、W2 两层 `wait/fc` 嵌套与输出。
- 认：未来延续像接力棒穿过每层冻结，守卫的输出是行程记录。
- 练习：再包一层 `dynamic-wind`，预测输出。
- 名字：`dynamic-wind`。

## 9. 结论

- 回收比较与分水岭：跳转目标成为值，其类型是 $¬p$；消耗否定与凭空造出否定。
- 程序是 $¬¬\text{Byte}$，退出延续由 OS 交来；`wait/fc` 的 $¬¬q$ 由日后的调用者交来（删减 `wait/fc` 后这句随之改）。

# 第二篇大纲

记录正文现在怎么走，不记论证，不抄代码。每节只写三样：回应什么问题，造了什么、认出了什么，第一次出现的名字。改叙事的 PR 先改这里，再改正文；只改措辞的 PR 不用动它。

标题：箭头指向何方：CPS 与否定翻译

主线：控制计算怎样得到显式延续表示，怎样用复合与绑定把它们接起来。具体运算律照常给出；与宿主连接的完整对应（往返的反方向、同构、交换图）不在本篇，见数学仓库 `series/positioning.md`。否定翻译从逻辑一侧解释这次构造意味着什么，不独自承担主线。

## 0. 开头

- 接第一篇的两根线头：构造性语言怎么支持经典推理；程序内部的相对 $⊥$。本篇回答第一根。

## 1. 求值顺序与 ANF

- 问题：嵌套表达式看不出求值顺序。
- 造：用 `let*` 给中间结果起名（ANF）；`let` 脱糖为 λ 调用。
- 认：等待结果的 λ 是**延续**；`(let ([y (f x)]) (g y))` 就是 `((∘ g f) x)`；`let` 嵌在 `b` 还是 `e` 里是**结合律**；换名的 `let` 是**单位律**；两条运算律说明，同一个求值顺序的不同 ANF 写法行为相同。
- 名字：ANF、redex、延续、`∘`、`id = (∘)`、结合律、单位律。
- 注意框：后一步用到多个名字的情形不在本文范围。

## 2. 延续与 CPS

- 问题：把延续取出来作为参数。
- 造：`fact/k`、`fib/k`；累积器版 `fact/k` 不增长闭包链。
- 认：递归调用与对延续的调用都成了尾调用；栈的增长搬到了堆上的闭包链。
- 名字：$¬$、$⊥$ 的类型读法，闭包链。

### 2.1 终结延续

- 问题：启动 CPS 函数交进去什么。
- 造：`exit` 不合适；用 `raise` 和 handler 造 `a->⊥`、`⊥->a`。
- 名字：终结延续、`ans`、`a->⊥`、`⊥->a`。

### 2.2 一等控制

- 问题：延续是一等值，不用 `call/cc` 能否写短路。
- 造：CPS 版 `mul`，遇零改调 `a->⊥`。
- 认：控制流就是选择调用哪条延续。
- 留下的抱怨：每个延续都得手写。

## 3. 否定的层次

- 问题：可变参数函数里，延续与操作数挤在同一层，只能靠位置约定区分。
- 造：柯里化把延续独立出来，得到 `neg`（延续在前）与 `cps`（延续在后）；`flip` 交换参数。
- 认：两者的类型是逆否律与 DNI 的推广；`flip` 是自己的逆，两行 `case→` 读法；`cps = (∘ flip neg)`；`(neg f)` 把 `f` 复合到延续前面，接两次就是闭包链。
- 名字：`neg`、`cps`、`flip`、`case→`、逆否律、DNI、`mul3`。
- 练习：只用 `neg`、`cps` 写出 `flip`。

### 3.1 三种箭头

- 问题：三种命题形状反复出现。
- 造：别名 `→𝒞`、`→𝒦`、`→𝒰`；`∘𝒰`（`∘` 反过来）；顺序反过来是因为 𝒰 的箭头方向与函数相反，引入反向箭头 `←`，𝒰 的箭头是两个否定之间的反向箭头，`∘𝒰` 就是反向复合 `⨾`；`∘𝒦`（经 `flip` 搬到 𝒰 复合再搬回）。
- 认：单位元是零元复合：`neg:id = (∘𝒰)`、`cps:id = (∘𝒦)`；展开 `∘𝒦` 两支，得到手写 `fib/k` 时的包法；三种复合都满足单位律、结合律。
- 名字：世界 𝒞、𝒦、𝒰，`∘𝒰`、`∘𝒦`、`neg:id`、`cps:id`、`←`、`⨾`。
- 练习：一支箭头的 `∘𝒦`。
- 注意框：纯性与「收到参数只造出等待延续的函数」的前提。

### 3.2 手中的延续

- 问题：第一篇用 `cc` 取得当前延续再交给 `proc`；一等控制一节说过，在 CPS 里延续参数就是当前延续。那 `call/cc` 在 𝒦、𝒰 里怎么写？
- 造：先不给类型，照 `call/cc` 自己的语义写：先写出两个箭头收到什么（函数体留空），再填上：`cps:call/cc` 把 `kp` 用 `cps` 提升一份交给 `proc`，另一份留下接住正常交回的结果；`neg:call/cc` 同理，提升用 `neg`。
- 运行：`cps:call/cc` 后接一步加 1，`cps:proc1` 正常交回（7），`cps:proc2` 调用交出去的延续后改走 `kp`，自己后面的加 1 被跳过（11）。
- 认：回顾第一篇 `call/cc` 的类型，用 𝒞 的写法记作 `¬𝒞` 与 `(→𝒞 (→𝒞 (¬𝒞 p) p) p)`；把 𝒞 换成 𝒦、𝒰，猜出两个类型，定义 `¬𝒦`、`¬𝒰`，再对照 `cps:call/cc` 的定义验证；它们是 Clavius 律在 𝒦、𝒰 里的样子；换了箭头就是另一条公式，展开别名全是宿主的箭头与否定，纯 λ 写得出，是直觉主义定理。方法明说一次：同一条经典定律换到 𝒦 或 𝒰 里写，就成了直觉主义定理。
- 名字：`cps:call/cc`、`neg:call/cc`、`¬𝒞`、`¬𝒦`、`¬𝒰`、Clavius 律。
- 练习：展开 `neg:call/cc` 的别名；写出 𝒦 自己的 DNE `cps:dne`（$¬_𝒦¬_𝒦p →_𝒦 p$）。
- 收尾：一等控制有了，写法还是 CPS，中间结果没有名字。

## 4. 再次隐藏延续

- 问题：用 `let` 把 CPS 的延续藏回去；`(1 + 2) × 3` 里 `cps:mul3` 用不上 `kk3`。
- 造：前一步交来编码，接好后交出去的也得是编码，所以要一个 $¬¬\text{Nat} → ¬¬\text{Nat}$ 的函数，读作 $¬¬\text{Nat} →_𝒦 \text{Nat}$，用 `∘𝒦` 接在 `cps:mul3` 前面；它原样交出，就是 `id`；展开得到手写 CPS 的样子 `(kk3 (λ (v) ((cps:mul3 v) k)))`。
- 认：这支箭头形似 DNE，却只是 $¬¬\text{Nat} → ¬¬\text{Nat}$，也不是 𝒦 自己的 DNE。它的类型是 `id` 取两次逆否：`neg` 的第二种读法（收到 𝒰 的箭头）；`neg² = (∘ neg neg)`，首次出现就限定交给它的是纯函数；那支箭头是 `(neg² id)`，记作 `neg²:id`。
- 认：`let` 与 `anf:let` 并排，分别是 `∘` 与 `∘𝒦` 的另一种写法；拿掉 `neg²:id` 的等式；两条运算律的绑定形状。
- 造：宏 `anf:let*-values`、`anf:begin`、`anf:let*`、`anf:if`、`anf:let/cc`，保留 `(∘𝒦 cps:kv neg²:id)` 的形状；宏只用 `∘𝒦` 与 `neg²:id` 接箭头，不改写箭头本身做的事；解释器 `anf:eval`，类型 $¬¬a → a$，扮演第一篇的操作系统。
- 名字：`kk3`、`cps:mul3`、`neg²`、`neg²:id`、`anf:` 系列、`anf:eval`。
- 练习：拿掉 `neg²:id` 的前提；推出四条运算律等式。

## 5. 嵌入语言

- 造：用 `cps` 提升宿主函数；嵌入语言版 `cps:mul`，本身是一支 𝒦 的箭头，交给 `anf:eval` 运行；`anf:let/cc` 交出的 `cps:return` 逃逸，与 3.2 的 `cps:proc2` 对照；阴阳谜题与 `cps:label`。
- 认：`cps:mul` 最后一步同时用到 `res` 与 `r`，宏的嵌套让它照样能写，只是不再是一串首尾相接的 `∘𝒦`。
- 名字：`cps:mul`。

### 5.1 计算的位置

- 认：每个绑定处有一个具体的延续；相邻两处只差 `(neg f)`；构造从 `a->⊥` 向内，运行时值向外。
- 名字：计算位置。

## 6. 编码与运行（标题候选）

写完嵌入语言之后，回答读者此时会问的两件事。

### 6.1 否定翻译（标题候选）

- 问题：`cps:mul` 用了经典控制，宿主的 `call/cc` 却没有出现；真的用纯函数写出了控制吗？
- 认：用 `cps:mul` 回看。控制是 `cps:return` 与 `anf:let*` 接好的延续之间的选择，`cps:call/cc` 是纯 λ；绑定 `(∘𝒦 cps:kv neg²:id) = (neg (flip cps:kv))`，由 4 节的展开推出；纯函数特例 `(∘𝒦 (cps f) neg²:id) = (neg² f)`；原语的纯性照实说（`cps:mul` 的原语是纯的；阴阳谜题的 `display` 与不终止不是）。
- 造：把宿主拆成 𝒞 与 𝒟：𝒟 拿掉会跳走的操作与输出，只留总会返回的计算；两者类型别名相同，区别在允许哪些宿主程序；`→𝒟`、`inj`。`neg²` 的类型写成 𝒟 到 𝒟；`neg` 的第二种读法同理；只用 λ 写成不够（自由变量、递归）。`cps:mul` 整个在 𝒟 里。
- 认：回答第一篇的问题，从逻辑一侧命名**否定翻译**，回收 3.2 的方法；名字挂在整段程序的改写上，不挂在 `neg²` 上（包一层改不掉黑盒里的 `call/cc`）；3.2 只是一个例子，不说完整形式翻译已经建立，不点名变体。
- 收尾：要拿到乘积还得写 `anf:eval`，里面有 `raise`。
- 名字：𝒟、`→𝒟`、`inj`、否定翻译。

### 6.2 填上延续参数（标题候选）

- 问题：𝒦 的箭头等着一个延续参数，谁来填？（为什么运行时又出现了 `raise`）
- 认：`anf:eval` 填终结延续 `a->⊥`，handler 接住答案，交回这次调用的后续；正常运行时是用 `raise` 与 handler 的跳转模拟了计算开始时的延续。
- 造：宿主的 `call/cc` 直接捕获当前延续，填进延续参数：`uncps = (∘ call/cc cps:f)`；`(+ 1 ((uncps cps:mul) …))` 两条路都回到 `(+ 1 _)`（25、1）。与 3.2 语义上呼应：那里在编码中实现 `call/cc`，交出当前延续；这里用宿主的 `call/cc` 运行编码，交入当前延续。
- 认：补上类型；`anf:eval` 的类型是 DNE，`uncps` 里的 `call/cc` 也是，`uncps` 的类型与 DNE 等价；`cps:id` 是 DNI，`(uncps (cps f)) = f`，DNI 接上 DNE 就是恒等。
- 收尾：编码在 𝒟 里完成；要从这里的编码中一般地取回结果，本篇仍借用了宿主的控制机制（`raise` 与 handler、`call/cc`）。
- 名字：`uncps`。

## 7. 结论

- 回看：同样的 `let*`，背后的复合从 `∘` 换成 `∘𝒦`；控制是延续之间的选择。

### 7.1 未解的线索

- $¬¬a$ 不是 $a$；𝒟 的纯函数一般交不出所需的 $¬a$，写不出对任意类型成立的解释器；终结延续与当前延续都是向宿主借的；流水线只用 $¬$ 之间的映射，从不需要 $¬$ 的元素；`a->⊥` 是借来的；$⊥$ 到底是什么。

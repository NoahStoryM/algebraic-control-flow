## 1. 求值顺序与 ANF

- 问题：嵌套表达式看不出求值顺序。
- 造：用 `let*` 给中间结果起名（ANF）；`let` 脱糖为 λ 调用。
- 认：等待结果的 λ 是**延续**；`(let ([y (f x)]) (g y))` 就是 `((∘ g f) x)`；`let*` 拆成嵌套的 `let`，每个绑定藏着一个延续。
- 注意框：后一步用到多个名字的情形不在本文范围。
- 名字：ANF、redex、延续、`∘`。

### 1.1 结合律与单位律

- 问题：`let` 写法不唯一（嵌在 `b`、嵌进 `e`、插入换名），定下的还是同一个顺序吗？
- 认：`let` 嵌在 `b` 还是 `e` 里是**结合律**；换名的 `let` 是**单位律**；两条运算律回答了这个问题。
- 造：照算的顺序写的复合 `⨾`，与 `let*` 的顺序一致；反向箭头 `←`，用 `←` 写出的 `⨾` 的类型和 `∘` 的类型形状一样。
- `∘`、`⨾` 只写两支的类型，变参签名只在附录。
- 名字：`id = (∘)`、结合律、单位律、`⨾`、`←`。

## 2. 延续与 CPS

- 问题：把延续取出来作为参数。
- 造：`fact/k`、`fib/k`；累积器版 `fact/k` 不增长闭包链。
- 认：递归调用与对延续的调用都成了尾调用；栈的增长搬到了堆上的闭包链。
- 造（Noah 10/22）：`(fact/k 3 k)` 的递归展开，先写出每层的 λ，再写成复合，延续一步步长成 `(∘ k mul3 mul2 mul1)`；展开之后才认出、命名**闭包链**；`mul3` 在这里命名；递归到底先乘 1、再乘 2、再乘 3。第 3 节回指这里，不再重列。
- 名字：$¬$、$⊥$ 的类型读法，闭包链。

### 2.1 终结延续

- 问题：启动 CPS 函数交进去什么。
- 造：`exit` 不合适；用 `raise` 和 handler 造 `a->⊥`、`⊥->a`。
- 命名（Noah 10/22）：仍在 `exit` 出场时命名终结延续，命名句接上闭包链：启动时交进去的延续就是闭包链的终点，值走完整条链最后抵达它。
- 名字：终结延续、`ans`、`a->⊥`、`⊥->a`。

### 2.2 一等控制

- 问题：延续是一等值，不用 `call/cc` 能否写短路。
- 造：CPS 版 `mul`，遇零改调 `a->⊥`。
- 认：控制流就是选择调用哪条延续。
- 不说「不需要任何特殊操作符」（Noah 10/23：`a->⊥` 靠 `raise`，留给第三篇 `cps*` 回收，这里只说切换延续是普通的函数调用）。

## 3. 把延续独立出来（原「否定的层次」）

### 7.1 回到宿主（原「填上延续参数」压短）

### 7.2 三种写法（原「走一圈」，Noah、Astra 10/23）

- 问题：反过来，CPS 箭头先运行回宿主、再提升，还是原来那支吗？展开 `(((cps (uncps cps:f)) a) kb)` 到 `((cps:f a) kb)`。
- 关键规律（Noah 的写法）：`(let ([a (call/cc kka)]) (ka a)) = (ka (call/cc kka)) ≈ (kka ka)`。注意框写前提：`ka` 交出去不再回来；排除 `dynamic-wind` 一类能分辨延续实现的上下文；第 3 节两层参数的前提。

- 认（Noah 10/23：这一节的核心是三种写法同构）：恒等对恒等（`id`、`cps:id`、`neg:id`），复合对复合（`(cps (∘ g f))` 与 `(∘𝒦 (cps g) (cps f))`；`∘𝒦` 与 `∘𝒰` 已在 5.2 对上），在 `≈` 意义下点名**同构**（*isomorphic*）并交代比较标准。𝒞 那一边不说同构。
- 名字：`≈`、图表、交换、交换图表、`unneg`、同构。

### 7.3 数一数 k（Noah 10/23 提，Astra 核；10/30 已裁：基础说明与「三重否定律」已在第一篇「否定塔」「代入 ¬q」，这里只留桥接，见文末「改写成 Scribble」）

- 名字里的 `k` 数否定的层数；同一个底类型 a 上，第 n 层是 ¬ⁿa。
- 相邻两层：多一层的那个正好可以接收少一层的那个，结果是 ⊥，即第一篇的矛盾律（不说「只有」，Astra 10/23）。
- +2：`cps:id`（DNI）。
- +2 与 -2 的两串等式（Noah 10/23）：延续与 CPS 一节开头的 `(k e) = ((λ (k) (k e)) …)` 从 `(kv v)` 走到 `(kkv kv)`，即 `(kp p) = (let ([kkp (cps:id p)]) (kkp kp))`；三种写法的规律倒过来读，从 `(kkp kp)` 走到 `(kp p)`，要 `call/cc`（DNE）。
- -2 不落底：第 3 层的 `kkkp` 遇上第 0 层的 `p`，`(((neg cps:id) kkkp) p) = (kkkp (cps:id p))`。点明 `(neg cps:id)` 是 DNI 的逆否 ¬¬¬p → ¬p，**三重否定律**（*law of triple negation*），直觉主义定理，不需要经典逻辑（Noah 10/23）；n ≥ 1 时第 n+2 层到第 n 层都是它。
- 落到第 0 层：对任意 a，没有统一的纯函数完成 ¬¬a → a（DNE）。不说「第 0 层不可达」；不当作对每个具体类型的不可能性证明（Astra 10/23）。
- Astra 10/24 审过（数学仓库 `math/background.md` 10.9 与第 10 组其余各条）：8 月的箭头（源, 目标）记账不收，旧推法不成立（`flip` 交换的是柯里化的两个参数，(2, 0) 的总层数也是二）。第一篇迁走基础说明以后，本节压成一段桥接，或并入 7.4 开头，不重讲否定塔。桥接里剩下的是本篇独有的三件事：第一篇的 DNI 在这里就是 `cps:id`；第一篇的三重否定构造在这里就是 `(neg cps:id)`；7.2 的运行等式 `(kp (call/cc kkp)) ≈ (kkp kp)` 表现为把计算交给延续。两个等式要分开：`kkp = (cps:id p)` 时 `(kkp kp) = (kp p)` 是直接 β 化简；任意 `kkp` 的那条依赖 7.2 的控制语义条件。7.4 的问题（`(cps call/cc)` 是什么）与第一篇不同，主旨不会被提前讲掉；2 → 2、1 → 3、4 → 2 是接口改变后的表示，取回原类型仍涉及运行边界。文献：Thielecke 1997 博士论文 *Categorical Structure of Continuation Passing Style*（application as DNE、thunking as DNI），整理文献时列上（凭记忆，未核原文）。

### 7.4 同一支箭头（Noah 10/23 提，Astra 核：只走 DNE 这条线）

- 开头（Noah 10/23）：照名字的约定 `cps:car` 就是 `(cps car)`，`cps:call/cc` 却不是 `(cps call/cc)`，它是整条 Clavius 律换写出来的。那 `(cps call/cc)`、`(neg call/cc)` 是什么？不换写定律，只把箭头搬过去。
- 收尾回扣：两者搬的是 DNE 这一支箭头，和 `cps:call/cc`、`neg:call/cc` 是两回事。
- 宿主 `call/cc` 照 DNE 读，¬¬a →𝒟 a，2 → 0。三种写法一一对应，它在另外两种写法里各是什么？
- CPS 箭头：`(((cps call/cc) kka) kb) = (kb (call/cc kka)) ≈ (kka kb)`，原样交出计算：`neg²:id` 在这里引入，并认出它就是 `(neg neg:id)`（名字的来由）（代码同 `id`，类型 `(→𝒦 (¬¬ a) a)`，与 `neg:id` 同一种情形；挪自原 7.4），2 → 2；`(uncps neg²:id) = call/cc`，工作来自 `uncps`。

- 收尾一句：接口改变后，原来的 2 → 0 变成 2 → 2、1 → 3，都不落底（不说「层数整体抬高」，Astra 10/23）。

- 名字：`join`、`join:id`、`cps->neg²`（练习）、否定翻译。

### 8.3 从 `mul` 到 `cps:mul`

- 开头（Astra 10/23）：`call/cc` 的例子展示一个经典操作怎样取得纯表示；提前返回一节已经把整段程序按结构改写成纯 CPS 程序。不说「把 `neg²` 递归到程序内部」：宏与控制改写不是这样定义的。

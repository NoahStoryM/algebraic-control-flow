主线：计算怎样得到纯表示、表示之后怎样保持复合（Noah 10/18 同意）。否定翻译从逻辑一侧解释这次构造意味着什么，不独自承担一般理论主线。

## 0. 开头

- 接第一篇的两根线头：构造性语言怎么支持经典推理；程序内部的相对 $⊥$。本篇回答第一根。

## 1. 求值顺序与 ANF

- 问题：嵌套表达式看不出求值顺序。
- 造：用 `let*` 给中间结果起名（ANF）；`let` 脱糖为 λ 调用。
- 认：等待结果的 λ 是**延续**；`(let ([y (f x)]) (g y))` 就是 `((∘ g f) x)`；`let` 嵌在 `b` 还是 `e` 里是**结合律**；换名的 `let` 是**单位律**。
- 名字：ANF、redex、延续、`∘`、`id = (∘)`、结合律、单位律。
- 注意框：后一步用到多个名字的情形不在本文范围。

## 2. 延续与 CPS

- 问题：把延续取出来作为参数。
- 造：`fact/k`、`fib/k`；累积器版 `fact/k` 不增长闭包链。
- 认：所有调用成了尾调用；栈的增长搬到了堆上的闭包链。
- 名字：$¬$、$⊥$ 的类型读法，闭包链。

### 2.1 终结延续

- 问题：启动 CPS 函数交进去什么。
- 造：`exit` 不合适；用 `raise` 和 handler 造 `a->⊥`、`⊥->a`。
- 名字：终结延续、`ans`、`a->⊥`、`⊥->a`。

### 2.2 一等控制

- 问题：延续是一等值，不用 `call/cc` 能否写短路。
- 造：CPS 版 `mul`，遇零改调 `a->⊥`。
- 认：控制流就是选择调用哪条延续。
- 留下的抱怨：每个延续都得手写。

## 3. 否定的层次

- 问题：可变参数函数分不开延续与操作数。
- 造：柯里化把延续独立出来，得到 `neg`（延续在前）与 `cps`（延续在后）；`flip` 交换参数。
- 认：两者的类型是逆否律与 DNI 的推广；`flip` 是自己的逆，两行 `case→` 读法；`cps = (∘ flip neg)`；`(neg f)` 把 `f` 复合到延续前面，接两次就是闭包链。
- 名字：`neg`、`cps`、`flip`、`case→`、逆否律、DNI、`mul3`。
- 练习：只用 `neg`、`cps` 写出 `flip`。

### 3.1 三种箭头

- 问题：三种命题形状反复出现。
- 造：别名 `→𝒞`、`→𝒦`、`→𝒰`；`∘𝒰`（`∘` 反过来）；在这里用一两句引入反向箭头 `←` 与反向复合 `⨾`：`∘𝒰` 里的 `reverse` 就是反向复合，𝒰 的箭头是两个否定之间的反向箭头（第三篇第 700 行回指）；`∘𝒦`（经 `flip` 搬到 𝒰 复合再搬回）。
- 认：单位元是零元复合：`neg:id = (∘𝒰)`、`cps:id = (∘𝒦)`；展开 `∘𝒦` 两支，得到手写 `fib/k` 时的包法；三种复合都满足单位律、结合律。
- 名字：世界 𝒞、𝒦、𝒰，`∘𝒰`、`∘𝒦`、`neg:id`、`cps:id`、`←`、`⨾`。
- 练习：一支箭头的 `∘𝒦`。
- 注意框：纯性与「收到参数只造出等待延续的函数」的前提。

### 3.2 两个 call/cc

- 问题：2.2 说过，在 CPS 里当前延续已经是参数。那 `call/cc` 在 𝒦、𝒰 里怎么写？
- 造：先不给类型，照 `call/cc` 自己的语义写：把延续参数记录的当前延续交给 `proc`。`cps:call/cc` 把 `kp` 提升成 𝒦 的箭头再交出，`neg:call/cc` 同理。两个定义并排，「提升一份、留一份」一眼可见。
- 运行：一个很短的调用，看清两条路径：正常交回结果，与调用交出去的延续后改走保存的 `kp`（例子试写时实测）。第 5 节 `anf:let/cc` 版 `mul` 再回指这里。
- 认：写出来以后补上类型，定义 `¬𝒦`、`¬𝒰`；展开别名，两者分别是 Clavius 律在 𝒦、𝒰 里的样子，是直觉主义定理，所以纯 λ 写得出。在这里把方法明说一次：同一条经典定律换个写法，就成了直觉主义定理。
- 名字：`cps:call/cc`、`neg:call/cc`、`¬𝒦`、`¬𝒰`、Clavius 律。
- 收尾：一等控制有了，写法还是 CPS，中间结果没有名字。
- 撤掉：「同构，所以也有 call/cc」。
- 练习（待定）：𝒦 自己的 DNE（`cps:dne`，`¬𝒦¬𝒦p →𝒦 p`）。试写时看叙事是否方便作练习，不方便就删（Noah 10/18）。

## 4. 再次隐藏延续

- 问题：用 `let` 把 CPS 的延续藏回去；`(1 + 2) × 3` 里 `cps:mul3` 用不上 `kk3`。
- 造：用 `∘𝒦` 在前面接一支 $¬¬\text{Nat} →_𝒦 \text{Nat}$ 的箭头，它什么也不做，就是 `id`；展开得到手写 CPS 的样子 `(kk3 (λ (v) ((cps:mul3 v) k)))`。
- 为什么要 $¬¬a → ¬¬b$ 由障碍本身说明：前一步交来编码，接好后还要能交给下一个绑定。
- 认：那支什么也不做的箭头类型是 $¬¬a → ¬¬a$，从类型看出它是 `id` 取两次逆否：`(neg (neg id))`。记 `neg² = (∘ neg neg)`，首次出现就说清纯函数的范围；那支箭头是 `(neg² id)`，改名 `neg²:id`，点明它形似 DNE 却不是 𝒦 自己的 DNE。
- 不起名 `cps->neg²`，正文只用 `(∘𝒦 cps:kv neg²:id)` 的复合形状（Noah 10/18：起名困难；单子要从 Kleisli 复合的角度定义）。
- 这次认出只服务于当前这个绑定，随后立即写宏，不在这里展开世界图、出口分类。
- 认：`let` 与 `anf:let` 并排，分别是 `∘` 与 `∘𝒦` 的另一种写法；拿掉 `neg²:id` 的等式；两条运算律的绑定形状。
- 造：宏 `anf:let*-values`、`anf:begin`、`anf:let*`、`anf:if`、`anf:let/cc`；解释器 `anf:eval`，给出类型 $¬¬a → a$。
- 名字：`kk3`、`cps:mul3`、`neg²`、`neg²:id`、`anf:` 系列、`anf:eval`。宏保留 `(∘𝒦 cps:kv neg²:id)` 的形状。
- 练习：拿掉 `neg²:id` 的前提；推出四条运算律等式。
- 就地说明：这些包装只用已有的复合与参数交换，不改写传入函数的行为；归入 𝒟 留到 6.2。

## 5. 嵌入语言

- 造：用 `cps` 提升宿主函数；嵌入语言版 `mul`（`anf:let/cc` 逃逸，回指 3.2）；阴阳谜题与 `cps:label`。

### 5.1 计算的位置

### 6.1 真的用纯函数写出了控制吗？

- 回看：`anf:let/cc` 版 `mul` 与宏。控制是显式延续之间的选择；3.2 的 `cps:call/cc` 是纯 λ；连接由纯函数实现：`(∘𝒦 cps:kv neg²:id) = (neg (flip cps:kv))`；纯函数特例 `(∘𝒦 (cps f) neg²:id) = (neg² f)`（「正好」，不用「碰巧」）。原语的纯性边界照实说（`display`、不终止的递归）。
- 造：把宿主拆成 𝒞 与 𝒟，说清两者类型别名相同，区别在允许哪些宿主程序；`inj`。第三篇第 678、700、877 行与第五篇第 455 行要用。
- 认：从逻辑一侧命名**否定翻译**：经典控制获得了构造性表达，这种类型与证明的系统改写与否定翻译相联系；回收 3.2 的方法与第一篇的问题，随后回到主线。名字不挂在 `neg²` 上；不能靠给黑盒函数包一层 `neg²` 代替程序的翻译；3.2 只是一个实例，不说成完整形式翻译已经建立，具体变体不点名。
- 纯性前提在 `neg` 第二种读法与 `neg²` 两处一起限定。
- 名字：𝒟、`→𝒟`、`inj`、否定翻译。
- 文献（定稿后统一整理）：Murthy 1990（Cornell 官方摘要，Astra 核过）；Griffin 1990 原文未核。

### 6.2 为什么运行时又出现了 `raise`？

- 认：`anf:eval` 的类型是 DNE。它给 $¬¬a$ 交进去终结延续 `a->⊥`，再由 handler 接住答案交出 $a$。正常运行时 `raise` 跳回调用 `anf:eval` 的位置：我们是用跳转机制模拟了计算开始时的延续（Noah）。用「模拟」，不说等价；不写单次、动态期间、重入、`call/ec`。
- 不改：2.1 的 `a->⊥`、`⊥->a`、`ans` 仍用 `raise` 与 handler；第三篇的异常单子与 A-翻译从这里接。
- 未定（Noah）：是否保留短版 `uncps`：宿主的 `call/cc` 也是 DNE，`uncps = (∘ call/cc cps:f)` 把编码箭头变回普通函数，加去程一行「DNI 接上 DNE 就是恒等」。若保留，不断言同构，不写反方向。不是第三篇的硬依赖（Astra 已核）。
- 收尾：编码在 𝒟 里完成，交出普通结果要向宿主借。

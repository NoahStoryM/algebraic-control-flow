# 第二篇大纲

记录正文现在怎么走，不记论证，不抄代码。每节只写三样：回应什么问题，造了什么、认出了什么，第一次出现的名字。改叙事的 PR 先改这里，再改正文；只改措辞的 PR 不用动它。

标题：箭头指向何方：CPS 与否定翻译

主线：控制计算怎样得到显式延续表示，怎样用复合与绑定把它们接起来。具体运算律照常给出；与宿主连接的完整对应（往返的反方向、同构、交换图）不在本篇，见数学仓库 `series/positioning.md`。否定翻译从逻辑一侧解释这次构造意味着什么，不独自承担主线。

## 0. 开头

- 接第一篇的两根线头：构造性语言怎么支持经典推理；程序内部的相对 $⊥$。本篇回答第一根。

## 1. 求值顺序与 ANF

- 问题：嵌套表达式看不出求值顺序。
- 造：用 `let*` 给中间结果起名（ANF）；`let` 脱糖为 λ 调用。
- 认：等待结果的 λ 是**延续**；`(let ([y (f x)]) (g y))` 就是 `((∘ g f) x)`。
- 问题：`let` 写法不唯一（嵌在 `b`、嵌进 `e`、插入换名），定下的还是同一个顺序吗？
- 认：`let` 嵌在 `b` 还是 `e` 里是**结合律**；换名的 `let` 是**单位律**；两条运算律回答了这个问题。
- 造：照算的顺序写的复合 `⨾`，与 `let*` 的顺序一致；反向箭头 `←`，用 `←` 写出的 `⨾` 的类型和 `∘` 的类型形状一样。
- 名字：ANF、redex、延续、`∘`、`id = (∘)`、结合律、单位律、`⨾`、`←`。
- 注意框：后一步用到多个名字的情形不在本文范围。

## 2. 延续与 CPS

- 问题：把延续取出来作为参数。
- 造：`fact/k`、`fib/k`；累积器版 `fact/k` 不增长闭包链。
- 认：递归调用与对延续的调用都成了尾调用；栈的增长搬到了堆上的闭包链。
- 名字：$¬$、$⊥$ 的类型读法，闭包链。

### 2.1 终结延续

- 问题：启动 CPS 函数交进去什么。
- 造：`exit` 不合适；用 `raise` 和 handler 造 `a->⊥`、`⊥->a`。
- 名字：终结延续、`ans`、`a->⊥`、`⊥->a`。

### 2.2 一等控制

- 问题：延续是一等值，不用 `call/cc` 能否写短路。
- 造：CPS 版 `mul`，遇零改调 `a->⊥`。
- 认：控制流就是选择调用哪条延续。
- 留下的抱怨：每个延续都得手写。

## 3. 否定的层次

- 问题：可变参数函数里，延续与操作数挤在同一层；无论放哪一头，都得一起交齐，没有一个值代表还没开始的计算（第一篇：程序是 $¬¬\text{Byte}$）。
- 造：柯里化把延续独立出来，得到 `neg`（延续在前）与 `cps`（延续在后）；`flip` 交换参数。
- 认：两者的类型是逆否律与 DNI 的推广；`flip` 是自己的逆，两行 `case→` 读法；`cps = (∘ flip neg)`；`(neg f)` 把 `f` 复合到延续前面，接两次就是闭包链。
- 名字：`neg`、`cps`、`flip`、`case→`、逆否律、DNI、`mul3`。
- 练习：只用 `neg`、`cps` 写出 `flip`。

### 3.1 三种箭头

- 问题：三种命题形状反复出现。
- 造：别名 `→𝒞`、`→𝒦`、`→𝒰`；`→𝒰` 用第 1 节的 `←` 写：𝒰 的箭头是两个否定之间的反向箭头，`∘𝒰` 就是 `⨾`；`∘𝒦`（经 `flip` 搬到 𝒰 复合再搬回）。
- 认：单位元是零元复合：`neg:id = (∘𝒰)`、`cps:id = (∘𝒦)`；展开 `∘𝒦` 两支，得到手写 `fib/k` 时的包法；三种复合都满足单位律、结合律。
- 名字：世界 𝒞、𝒦、𝒰，`∘𝒰`、`∘𝒦`、`neg:id`、`cps:id`。
- 练习：一支箭头的 `∘𝒦`。
- 注意框：纯性与「收到参数只造出等待延续的函数」的前提。

### 3.2 手中的延续

- 问题：第一篇用 `cc` 取得当前延续再交给 `proc`；一等控制一节说过，在 CPS 里延续参数就是当前延续。那 `call/cc` 在 𝒦、𝒰 里怎么写？
- 造：先不给类型，照 `call/cc` 自己的语义写：先写出两个箭头收到什么（函数体留空），再填上：`cps:call/cc` 把 `kp` 用 `cps` 提升一份交给 `proc`，另一份留下接住正常交回的结果；`neg:call/cc` 同理，提升用 `neg`。
- 运行：`cps:call/cc` 后接一步加 1，`cps:proc1` 正常交回（7），`cps:proc2` 调用交出去的延续后改走 `kp`，自己后面的加 1 被跳过（11）。
- 名字：`cps:call/cc`、`neg:call/cc`。

### 3.3 新世界下的 Clavius 律

- 问题：两个新 `call/cc` 的类型是什么？只用 λ 怎么写出了经典定律？
- 认：从定义读出类型：结果类型记作 `p`，`kp` 是 `(¬ p)`，`(cps kp)` 是 `(→𝒦 p ⊥)`，定义 `¬𝒦`、`¬𝒰`；`cps:proc` 交回的计算交给 `kp`，是 `(→𝒦 (¬𝒦 p) p)`；于是得到 `cps:call/cc` 的类型，`neg:call/cc` 同理。再与第一篇 `call/cc` 的类型（用 𝒞 的写法记作 `¬𝒞`）并排，认出 Clavius 律在 𝒦、𝒰 里的样子。
- 小高潮：第一篇的分水岭说 `call/cc` 要凭空造出 $¬p$，`cps:call/cc` 却只用 λ。展开一层 $(¬_𝒦 p → ¬¬p) → ¬p → ⊥$：$¬p$ 是参数 `kp`；`(cps kp)` 由它加工而来，𝒦 里同样凭空造不出非空类型的否定；`cps:call/cc` 只消耗交到手里的否定，是分水岭构造性那一侧。展开后的公式不是宿主的 Clavius 律，有纯 λ 项，是直觉主义定理。方法明说一次：同一条经典定律换到 𝒦 或 𝒰 里写，就成了直觉主义定理；宿主要捕获的延续成了显式的参数。分量只到一条定律；这里提出的「交给 `proc` 的否定从哪里来」由 5.1、6.2 各答一半，全篇高潮在第 7 节合起来回答。
- 名字：`¬𝒞`、`¬𝒦`、`¬𝒰`、Clavius 律。
- 练习：推出 `neg:call/cc` 的类型（放在类型块之后）。
- 收尾：一等控制有了，写法还是 CPS，中间结果没有名字。

## 4. 再次隐藏延续

- 问题：用 `let` 把 CPS 的延续藏回去。`(1 + 2) × 3` 先摆出两种已有写法：手写 CPS 的 λ 与 `((∘𝒦 cps:mul3 cps:+) 1 2)`，两者相等；想要的第三种 `anf:let` 意思应与它们一样。
- 名字：`cps:mul3`。

### 4.1 接上一段计算（标题候选）

- 问题：先试着把 `anf:let` 当作 `let` 读。回指延续与 CPS 一节的拆法：`let` 手里有 `k` 与 `e`，`(k e)` 类型对得上；照样拆 `anf:let`，手里是 `cps:mul3` 与 `kk3`，对不上。`let` 背后是 `∘`，要的是 `∘𝒦`。
- 造：宏拿到的是整个右边，算出一段计算 `kk3`，没有单独的 `cps:+` 与 `1`、`2`，于是在 `cps:mul3` 前面接一支 `X`：`((∘𝒦 cps:mul3 X) kk3)`，类型 $¬¬\text{Nat} →_𝒦 \text{Nat}$，展开是 $¬¬\text{Nat} → ¬¬\text{Nat}$。交给两边一个延续 `k` 照 `∘𝒦` 展开，与要的复合 `((∘𝒦 cps:mul3 cps:+) 1 2)` 对一对（中间一行是开头的手写版），推出 `(X kk3)` 得是 `kk3`：`(define (neg²:id kkv) kkv)`。
- 认：它是 $¬¬\text{Nat}$ 上的 `id`，形似 DNE，展开只是原样交出；`((∘𝒦 cps:mul3 neg²:id) (cps:+ 1 2)) = ((∘𝒦 cps:mul3 cps:+) 1 2)`，三种写法合上（4.2 的一般等式是它的推广）。
- 名字：`kk3`、`neg²:id`。
- 练习：只用 `neg` 和 `id` 写出与 `neg²:id` 行为相同的函数（名字的来历；`neg²` 在 6.1 定义）。

### 4.2 绑定就是复合（标题候选）

- 认：一般形式 `((∘𝒦 cps:kv neg²:id) kkv)`；右边是一次调用时，4.1 的推导照样走得通：`((∘𝒦 cps:kv neg²:id) (cps:f x)) = ((∘𝒦 cps:kv cps:f) x)`，正是 4.1 想要的 `∘𝒦`；与宿主并排：`(let ([y (f x)]) (g y)) = ((∘ g f) x)`、`(anf:let ([y (cps:f x)]) (cps:g y)) = ((∘𝒦 cps:g cps:f) x)`；两条运算律的绑定形状。
- 练习：上面那条等式的前提（收到参数就打印时）；推出四条运算律等式。

### 4.3 写成宏（标题候选）

- 造：例子展开出的具体代码；宏 `anf:let*-values`、`anf:begin`、`anf:let*`、`anf:if`、`anf:let/cc`，保留 `(∘𝒦 cps:kv neg²:id)` 的形状；宏只用 `∘𝒦` 与 `neg²:id` 接箭头，不改写箭头本身做的事；宏充当编译器。
- 名字：`anf:` 系列。

## 5. 嵌入语言

- 造：用 `cps` 提升宿主函数；嵌入语言版 `cps:mul`，本身是一支 𝒦 的箭头；要运行它，引入解释器 `anf:eval`，类型 $¬¬a → a$，扮演第一篇的操作系统；`anf:let/cc` 交出的 `cps:return` 逃逸，与 3.2 的 `cps:proc2` 对照；阴阳谜题与 `cps:label`。
- 认：`cps:mul` 最后一步同时用到 `res` 与 `r`，宏的嵌套让它照样能写，只是不再是一串首尾相接的 `∘𝒦`。
- 名字：`cps:mul`、`anf:eval`。

### 5.1 计算的位置

- 问题：`(cps:label)` 把位置捕获成值（`cps:yin`、`cps:yang`）。至此注意力一直在否定类型上（`neg`、`flip`、`∘𝒦` 在 $¬$ 之间搬运）；换个角度看否定类型的具体元素：运行时的一条延续、一个位置，它们怎样变化。没有被捕获的位置也是这样的元素。
- 认：ANF 版 `fib` 的每个绑定处有一个具体的延续，是 $¬\text{Natural}$ 的一个值，标出程序走到哪里：计算位置（元素即位置）。`kn-2 = (∘ kw fib) = ((neg fib) kw)`：`(neg fib)` 在两个延续类型之间映射，交给它具体的 `kw`，交出具体的 `kn-2`，把一个位置映射成另一个位置；一般地，`f` 连起 `kp` 与 `kq` 的条件是 `kp = ((neg f) kq)`（走一步即箭头）。两种读法：构造从 `a->⊥` 向内，运行时值向外，顺着 `let*` 链走。不点范畴论名字（数学背景 1.4）。
- 名字：计算位置。

## 6. 编码与运行（标题候选）

写完嵌入语言之后，回答读者此时会问的两件事。

### 6.1 否定翻译（标题候选）

- 问题：阴阳谜题与 `cps:mul` 用同一套宏、同一个 `cps:call/cc`，前者却在打印、永不结束；说控制「用纯函数写出来」，纯的是哪一部分？
- 造：把宿主拆成 𝒞 与 𝒟：𝒟 只留没有可观察副作用、在合法输入上总会返回的程序，函数参数也按此理解；两者类型别名相同，别名不检查这些条件；`→𝒟`、`inj`。
- 认：用 `cps:mul` 回看。`cps:return` 来自 `cps:call/cc`，回指 3.3，一句。绑定先用 4.1 的 `cps:mul3`、`kk3` 推：`(((∘𝒦 cps:mul3 neg²:id) kk3) k) = (((neg (neg mul3)) kk3) k)`，只用 `neg` 的定义；`kk3` 站上延续位置的理由：$¬¬\text{Nat}$ 就是 $¬(¬\text{Nat})$。定义 `neg² = (∘ neg neg)`，类型写成 𝒟 到 𝒟（第二次 `neg` 是第二种读法，文字给出类型）；4.1 的练习兑现：`neg²:id` 就是 `(neg² id)`。一般的绑定（含控制的 `cps:kv`）：`(flip cps:kv)` 接替 `(neg mul3)`，`(∘𝒦 cps:kv neg²:id) = (neg (flip cps:kv))`。这些组合子只用 λ、应用、复合与有限参数表上的 `apply`、`map`、`reverse`，交给它们的在 𝒟 里，得到的也在 𝒟 里；`cps:mul` 的原语是纯的，`car`、`cdr` 在非空分支调用，递归沿更短的列表，所以整个在 𝒟 里；阴阳谜题的输出与不终止在 𝒟 之外。
- 认：第一篇说过经典控制流可编码成显式的延续传递，名为**否定翻译**；它在本篇这几段程序上有了所指：控制写成纯 CPS 构造，每一步写成 𝒦 的箭头，宏按原结构用 `∘𝒦` 接起来；回收 3.3 的方法，推广到整段程序。名字挂在程序的改写上，不挂在 `neg²` 上（包一层改不掉黑盒里的 `call/cc`）。
- 收尾：只认领第一篇问题里编码的一半：经典控制写成了 𝒟 里的纯程序，结果裹上一层 $¬¬$；这样的程序还要有人运行。
- 名字：𝒟、`→𝒟`、`inj`、`neg²`、否定翻译。

### 6.2 填上延续参数（标题候选）

- 问题：`(+ 1 (anf:eval (cps:mul …)))` 得 25 与 1；`anf:eval` 交进去的是一调用就 `raise` 的 `a->⊥`，结果怎么回到了 `(+ 1 _)`？
- 认：handler 接住答案，交回调用处；计算真正的去处是调用处之后的工作，`raise` 与 handler 的跳转模拟了它。
- 造：宿主的 `call/cc` 直接捕获当前延续，填进延续参数：`uncps = (∘ call/cc cps:f)`（类型与定义同块）；放进同一个 `(+ 1 _)`，结果相同，交给的是 `call/cc` 填进去的那条延续本身。与 3.2 语义上呼应：那里在编码中实现 `call/cc`，交出当前延续；这里用宿主的 `call/cc` 运行编码，交入当前延续。
- 认：`anf:eval` 与 `uncps` 里的 `call/cc` 类型都是 DNE；`uncps` 的类型与 DNE 两个方向都写出（单值类型上的常函数；定义本身就是接一次 DNE）。`cps:id` 是 DNI；对纯 `f`，`(cps f)` 与 `(∘ cps:id f)` 行为相同（区别只在 `f` 何时调用）；`(uncps (cps f)) = f`：对这里用 `call/cc` 实现的 DNE，DNI 接上它就是恒等。
- 「借宿主」不在本节说，留给第 7 节。
- 名字：`uncps`。

## 7. 结论

- 高潮：回答 3.3 的问题「交给 `proc` 的否定从哪里来」：来自 `kp`；回收 5.1 从右往左读的 `kp = ((neg f) kq)`：这里的纯编码中，各处延续从出口那条出发，由纯构造一环环接出（5.1），出口那一条由 `anf:eval` 或 `call/cc` 交进来（6.2）。第一篇分水岭的分界线还在，挪到了程序的边界上：边界以内，消耗、变换延续的工作（`neg`、`flip`、`∘𝒦`、`cps:call/cc`）都是 𝒟 里的纯函数，控制是在已有延续之间选择；边界上，一次运行需要宿主提供一条终结延续（`anf:eval` 交入现成的 `a->⊥` 并用 handler 接回答案，`uncps` 交入 `call/cc` 捕获的当前延续）。由此回答第一篇的问题：经典控制有了纯的 CPS 表示，留在程序里；提供终结延续、运行编码并交回答案的 DNE 留在编码之外的运行边界上。不说纯片段因此获得了一般的 DNE，也不把提供终结延续等同于 DNE。

### 7.1 未解的线索

- $¬¬a$ 不是 $a$；𝒟 一般不能自行提供终结延续，也没有对任意类型成立的纯函数从这里的编码中取回结果；`anf:eval` 借来的 `a->⊥` 的跳转来自 `raise`，类型是 $⊥$（第一篇的 `goto`）；`a->⊥` 与 `⊥->a` 这对名字；接回开头第二根线头（相对的 $⊥$）：$⊥$ 到底是什么。

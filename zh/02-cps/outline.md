# 第二篇大纲

记录正文现在怎么走，不记论证，不抄代码。每节只写三样：回应什么问题，造了什么、认出了什么，第一次出现的名字。改叙事的 PR 先改这里，再改正文；只改措辞的 PR 不用动它。

标题：箭头指向何方：CPS 与否定翻译

## 0. 开头

- 接第一篇的两根线头：构造性语言怎么支持经典推理；程序内部的相对 $⊥$。本篇回答第一根。

## 1. 求值顺序与 ANF

- 问题：嵌套表达式看不出求值顺序。
- 造：用 `let*` 给中间结果起名（ANF）；`let` 脱糖为 λ 调用。
- 认：等待结果的 λ 是**延续**；`(let ([y (f x)]) (g y))` 就是 `((∘ g f) x)`；`let` 嵌在 `b` 还是 `e` 里是**结合律**；换名的 `let` 是**单位律**。
- 名字：ANF、redex、延续、`∘`、`id = (∘)`、结合律、单位律。
- 注意框：后一步用到多个名字的情形不在本文范围。

## 2. 延续与 CPS

- 问题：把延续取出来作为参数。
- 造：`fact/k`、`fib/k`；累积器版 `fact/k` 不增长闭包链。
- 认：所有调用成了尾调用；栈的增长搬到了堆上的闭包链。
- 名字：$¬$、$⊥$ 的类型读法，闭包链。

### 2.1 终结延续

- 问题：启动 CPS 函数交进去什么。
- 造：`exit` 不合适；用 `raise` 和 handler 造 `a->⊥`、`⊥->a`。
- 名字：终结延续、`ans`、`a->⊥`、`⊥->a`。

### 2.2 一等控制

- 问题：延续是一等值，不用 `call/cc` 能否写短路。
- 造：CPS 版 `mul`，遇零改调 `a->⊥`。
- 认：控制流就是选择调用哪条延续。
- 留下的抱怨：每个延续都得手写。

## 3. 否定的层次

- 问题：可变参数函数分不开延续与操作数。
- 造：柯里化把延续独立出来，得到 `neg`（延续在前）与 `cps`（延续在后）；`flip` 交换参数。
- 认：两者的类型是逆否律与 DNI 的推广；`flip` 是自己的逆，两行 `case→` 读法；`cps = (∘ flip neg)`；`(neg f)` 把 `f` 复合到延续前面，接两次就是闭包链。
- 名字：`neg`、`cps`、`flip`、`case→`、逆否律、DNI、`mul3`。
- 练习：只用 `neg`、`cps` 写出 `flip`。

### 3.1 三种箭头

- 问题：三种命题形状反复出现。
- 造：别名 `→𝒞`、`→𝒦`、`→𝒰`；`∘𝒰`（`∘` 反过来）；`∘𝒦`（经 `flip` 搬到 𝒰 复合再搬回）。
- 认：单位元是零元复合：`neg:id = (∘𝒰)`、`cps:id = (∘𝒦)`；展开 `∘𝒦` 两支，得到手写 `fib/k` 时的包法；三种复合都满足单位律、结合律。
- 名字：世界 𝒞、𝒦、𝒰，`∘𝒰`、`∘𝒦`、`neg:id`、`cps:id`。
- 练习：一支箭头的 `∘𝒦`。
- 注意框：纯性与「收到参数只造出等待延续的函数」的前提。

### 3.2 两个 call/cc

- 问题：2.2 说过，在 CPS 里当前延续已经是参数。那 `call/cc` 在 𝒦、𝒰 里怎么写？
- 造：先不给类型，照 `call/cc` 自己的语义写：把延续参数记录的当前延续交给 `proc`。`cps:call/cc` 把 `kp` 提升成 𝒦 的箭头再交出，`neg:call/cc` 同理。两个定义并排，「提升一份、留一份」一眼可见。
- 运行：一个很短的调用，看清两条路径：正常交回结果，与调用交出去的延续后改走保存的 `kp`（例子试写时实测）。第 5 节 `anf:let/cc` 版 `mul` 再回指这里。
- 认：写出来以后补上类型，定义 `¬𝒦`、`¬𝒰`；展开别名，两者分别是 Clavius 律在 𝒦、𝒰 里的样子，是直觉主义定理，所以纯 λ 写得出。在这里把方法明说一次：同一条经典定律换个写法，就成了直觉主义定理。
- 名字：`cps:call/cc`、`neg:call/cc`、`¬𝒦`、`¬𝒰`、Clavius 律。
- 收尾：一等控制有了，写法还是 CPS，中间结果没有名字。
- 撤掉：「同构，所以也有 call/cc」。
- 练习（待定）：𝒦 自己的 DNE（`cps:dne`，`¬𝒦¬𝒦p →𝒦 p`）。试写时看叙事是否方便作练习，不方便就删（Noah 10/18）。

## 4. 再次隐藏延续

- 问题：用 `let` 把 CPS 的延续藏回去；`(1 + 2) × 3` 里 `cps:mul3` 用不上 `kk3`。
- 造：用 `∘𝒦` 在前面接一支 $¬¬\text{Nat} →_𝒦 \text{Nat}$ 的箭头，它什么也不做，就是 `id`；展开得到手写 CPS 的样子 `(kk3 (λ (v) ((cps:mul3 v) k)))`。
- 为什么要 $¬¬a → ¬¬b$ 由障碍本身说明：前一步交来编码，接好后还要能交给下一个绑定。
- 认：那支什么也不做的箭头类型是 $¬¬a → ¬¬a$，从类型看出它是 `id` 取两次逆否：`(neg (neg id))`。记 `neg² = (∘ neg neg)`，首次出现就说清纯函数的范围；那支箭头是 `(neg² id)`，改名 `neg²:id`，点明它形似 DNE 却不是 𝒦 自己的 DNE。
- 不起名 `cps->neg²`，正文只用 `(∘𝒦 cps:kv neg²:id)` 的复合形状（Noah 10/18：起名困难；单子要从 Kleisli 复合的角度定义）。
- 这次认出只服务于当前这个绑定，随后立即写宏，不在这里展开世界图、出口分类。
- 认：`let` 与 `anf:let` 并排，分别是 `∘` 与 `∘𝒦` 的另一种写法；拿掉 `neg²:id` 的等式；两条运算律的绑定形状。
- 造：宏 `anf:let*-values`、`anf:begin`、`anf:let*`、`anf:if`、`anf:let/cc`；解释器 `anf:eval`，给出类型 $¬¬a → a$。
- 名字：`kk3`、`cps:mul3`、`neg²`、`neg²:id`、`anf:` 系列、`anf:eval`。宏保留 `(∘𝒦 cps:kv neg²:id)` 的形状。
- 练习：拿掉 `neg²:id` 的前提；推出四条运算律等式。
- 就地说明：这些包装只用已有的复合与参数交换，不改写传入函数的行为；归入 𝒟 留到 6.2。

## 5. 嵌入语言

- 造：用 `cps` 提升宿主函数；嵌入语言版 `mul`（`anf:let/cc` 逃逸，回指 3.2）；阴阳谜题与 `cps:label`。

### 5.1 计算的位置

- 认：每个绑定处有一个具体的延续；相邻两处只差 `(neg f)`；构造从 `a->⊥` 向内，运行时值向外。
- 名字：计算位置。

## 6. 经典与构造

由原来的「经典与构造」「落回 𝒟」「否定翻译」三节改写合并，挪到程序写完之后。两个小节各回答一个读者的问题，图表只总结答案。

### 6.1 终结延续与当前延续

- 问题：刚才 `anf:eval` 怎样交出普通结果？
- 认：`anf:eval` 的类型是 DNE。它给 $¬¬a$ 交进去终结延续 `a->⊥`，再由 handler 接住答案交出 $a$。交入延续是启动，交回答案也要说完整（Sol）。
- 认：正常运行时，`raise` 跳回的就是调用 `anf:eval` 的位置。我们其实是用跳转机制（`raise` 与 handler）模拟了计算开始时的延续（Noah 10/18）。用「模拟」，不说两者等价。
- 问题：宿主的 `call/cc` 也是 DNE，它不用模拟，直接把调用处的当前延续交给编码计算。有了它，已经写好的 𝒦 箭头能不能恢复成普通的 $p → q$ 接口？
- 造：`uncps = (∘ call/cc cps:f)`；验证两个方向都是恒等，往返论证用到的正是 `call/cc` 直接交入当前延续这件事；$𝒦 ≅ 𝒞$；`unneg`；三个世界同构，三世界交换图。
- 不进正文：模拟与 `call/cc` 在边角情况的差别（嵌套 `anf:eval`、保存后重用 `a->⊥`，Sol 在 8.10 上核过），以及单次、动态期间、重入、`call/ec` 的分类；正文不写任何未经证明的「一次性」「生存期」性质。
- 不改：2.1 的 `a->⊥`、`⊥->a`、`ans` 仍用 `raise` 与 handler，不换成 `call/cc` 捕获的延续。第三篇的异常单子与 A-翻译从这里接（Noah 10/18）。
- 认：「计算的位置」刚讲过每个位置上的具体延续；`anf:eval` 模拟的是链底那条，`call/cc` 交进去的是当前位置那条。
- 收尾对照（一句）：恢复普通接口要借宿主的 `call/cc`；3.2 里留在 𝒦、𝒰 的 `call/cc` 却用纯 λ 写得出。
- 名字：DNE（「与 DNE 等价」的措辞）、`uncps`、`unneg`、交换图表。
- 注意框：同构的三个前提。

### 6.2 否定翻译

- 问题：编码本身借了宿主的什么？回看整段程序，`neg`、`flip`、`∘𝒦`、`cps:call/cc`、`neg²:id` 和宏全是纯 λ；借宿主的地方是 `uncps` 的 `call/cc`、`anf:eval` 的 `raise`，以及原语的输出、不终止的递归。
- 造：把宿主拆成 𝒞 与 𝒟，说清两者类型别名相同，区别在允许哪些宿主程序（`display` 的口径统一）；`inj`。
- 认：𝒰 箭头读回宿主时两端对调；`←`、`⨾`，`∘𝒰 = ⨾`；`neg` 的 `case→` 第二行。这一段只回答：为什么绑定的接法落在 𝒟 里。展开 `(∘𝒦 cps:kv neg²:id)`，认出它就是 `((neg (flip cps:kv)) kkv)`：`neg` 用在了 𝒰 的箭头上，正是第二种读法。
- 认：两个经典出口与它们的构造性替身并排，逆否的构造性替身只作回看；纯性前提在 `neg` 第二种读法与 `neg²` 两处一起限定。
- 造：四世界表（「逻辑」栏改名「成立的定律」）与四世界图。概括上是在三世界图上加 𝒟，但源端 $a → b$ 与落点 $¬¬a → ¬¬b$ 分开画，不机械补边宣称任意路径都交换；往返的条件照样保留。
- 认：命名**否定翻译**，指整段程序的翻译；`neg²` 是它在纯函数上的类型层特例，签名 𝒟 → 𝒟。
- 名字：𝒟、`→𝒟`、`inj`、`←`、`⨾`、否定翻译。
- 练习：保留「从 𝒦 经 𝒰 到 𝒟」，答案是 `(∘ neg flip)`，正文不起名。
- 注意框：Kuroda 与 Kolmogorov 的变体（措辞待核）。
- 撤掉：「能不能直接落回 𝒟」作为动机；「这是全部经典能力的来源」。

## 7. 结论

- 回看：同样的 `let*`，背后的复合从 `∘` 换成 `∘𝒦`。只从已经确认的运行边界出发，不再清点全部构造。

### 7.1 未解的线索

- 𝒟 能编码、能复合；终结延续与当前延续，一般地都要向宿主借（`raise`、`call/cc`），纯构造性片段不能对任意 $a$ 提供所需的 $¬a$（不写成 𝒟 里绝无任何否定类型的函数）；`a->⊥` 是借来的；$⊥$ 到底是什么。

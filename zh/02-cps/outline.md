# 第二篇大纲

记录正文现在怎么走，不记论证，不抄代码。每节只写三样：回应什么问题，造了什么、认出了什么，第一次出现的名字。改叙事的 PR 先改这里，再改正文；只改措辞的 PR 不用动它。

标题：箭头指向何方：CPS 与否定翻译

## 0. 开头

- 接第一篇的两根线头：构造性语言怎么支持经典推理；程序内部的相对 $⊥$。本篇回答第一根。

## 1. 求值顺序与 ANF

- 问题：嵌套表达式看不出求值顺序。
- 造：用 `let*` 给中间结果起名（ANF）；`let` 脱糖为 λ 调用。
- 认：等待结果的 λ 是**延续**；`(let ([y (f x)]) (g y))` 就是 `((∘ g f) x)`；`let` 嵌在 `b` 还是 `e` 里是**结合律**；换名的 `let` 是**单位律**。
- 名字：ANF、redex、延续、`∘`、`id = (∘)`、结合律、单位律。
- 注意框：后一步用到多个名字的情形不在本文范围。

## 2. 延续与 CPS

- 问题：把延续取出来作为参数。
- 造：`fact/k`、`fib/k`；累积器版 `fact/k` 不增长闭包链。
- 认：所有调用成了尾调用；栈的增长搬到了堆上的闭包链。
- 名字：$¬$、$⊥$ 的类型读法，闭包链。

### 2.1 终结延续

- 问题：启动 CPS 函数交进去什么。
- 造：`exit` 不合适；用 `raise` 和 handler 造 `a->⊥`、`⊥->a`。
- 名字：终结延续、`ans`、`a->⊥`、`⊥->a`。

### 2.2 一等控制

- 问题：延续是一等值，不用 `call/cc` 能否写短路。
- 造：CPS 版 `mul`，遇零改调 `a->⊥`。
- 认：控制流就是选择调用哪条延续。
- 留下的抱怨：每个延续都得手写。

## 3. 否定的层次

- 问题：可变参数函数分不开延续与操作数。
- 造：柯里化把延续独立出来，得到 `neg`（延续在前）与 `cps`（延续在后）；`flip` 交换参数。
- 认：两者的类型是逆否律与 DNI 的推广；`flip` 是自己的逆，两行 `case→` 读法；`cps = (∘ flip neg)`；`(neg f)` 把 `f` 复合到延续前面，接两次就是闭包链。
- 名字：`neg`、`cps`、`flip`、`case→`、逆否律、DNI、`mul3`。
- 练习：只用 `neg`、`cps` 写出 `flip`。

### 3.1 三种箭头

- 问题：三种命题形状反复出现。
- 造：别名 `→𝒞`、`→𝒦`、`→𝒰`；`∘𝒰`（`∘` 反过来）；`∘𝒦`（经 `flip` 搬到 𝒰 复合再搬回）。
- 认：单位元是零元复合：`neg:id = (∘𝒰)`、`cps:id = (∘𝒦)`；展开 `∘𝒦` 两支，得到手写 `fib/k` 时的包法；三种复合都满足单位律、结合律。
- 名字：世界 𝒞、𝒦、𝒰，`∘𝒰`、`∘𝒦`、`neg:id`、`cps:id`。
- 练习：一支箭头的 `∘𝒦`。
- 注意框：纯性与「收到参数只造出等待延续的函数」的前提。

### 3.2 两个 call/cc

- 问题：2.2 说过，在 CPS 里当前延续已经是参数。那 `call/cc` 在 𝒦、𝒰 里怎么写？
- 造：先不给类型，照 `call/cc` 自己的语义写：把延续参数记录的当前延续交给 `proc`。`cps:call/cc` 把 `kp` 提升成 𝒦 的箭头再交出，`neg:call/cc` 同理。两个定义并排，「提升一份、留一份」一眼可见。
- 运行：一个很短的调用，看清两条路径：正常交回结果，与调用交出去的延续后改走保存的 `kp`（例子试写时实测）。第 6 节 `anf:let/cc` 版 `mul` 再回指这里。
- 认：写出来以后补上类型，定义 `¬𝒦`、`¬𝒰`；展开别名，两者分别是 Clavius 律在 𝒦、𝒰 里的样子，是直觉主义定理，所以纯 λ 写得出。在这里把方法明说一次：同一条经典定律换个写法，就成了直觉主义定理。
- 名字：`cps:call/cc`、`neg:call/cc`、`¬𝒦`、`¬𝒰`、Clavius 律。
- 未定：𝒦 自己的 DNE（`cps:dne`，`¬𝒦¬𝒦p →𝒦 p`）作练习还是不提（主线不再用它说明方法）。

## 4. 经典与构造

- 问题：如果宿主本身也有 `call/cc`，三个世界之间是什么关系？
- 认：从 𝒦、𝒰 回到 𝒞，类型是 DNE 与逆否律之逆，经典定理（「与 DNE 等价」），要借宿主的 `call/cc`。
- 造：`uncps = (∘ call/cc cps:f)`；验证两个方向都是恒等，$𝒦 ≅ 𝒞$；`unneg`；三个世界同构，给出交换图表。
- 收尾对照（一句）：回到 𝒞 要借宿主的 `call/cc`；3.2 里留在 𝒦、𝒰 的 `call/cc` 却用纯 λ 写得出。不预告 𝒟。
- 名字：DNE、`uncps`、`unneg`、交换图表。
- 注意框：同构的三个前提。
- 撤掉：「同构，所以也有 call/cc」。
- 收尾：一等控制有了，写法还是 CPS，中间结果没有名字。

## 5. 再次隐藏延续

- 问题：用 `let` 把 CPS 的延续藏回去；`(1 + 2) × 3` 里 `cps:mul3` 用不上 `kk3`。
- 造：用 `∘𝒦` 在前面接一支 $¬¬\text{Nat} →_𝒦 \text{Nat}$ 的箭头，它什么也不做，就是 `id`；展开得到手写 CPS 的样子 `(kk3 (λ (v) ((cps:mul3 v) k)))`。
- 认（一）：展开式就是 `((neg (flip cps:mul3)) kk3)`，`neg` 用在了 𝒰 的箭头上，类型是第一行的代入实例。为什么要 $¬¬a → ¬¬b$ 由障碍本身说明：前一步交来编码，接好后还要能交给下一个绑定。起名 `cps->neg² = (∘ neg flip)`。
- 认（二）：对纯函数，`(cps->neg² (cps f)) = (neg (neg f))`，记 `neg²`；那支 `id` 是 `(neg² id)`，改名 `neg²:id`；`(∘𝒦 cps:kv neg²:id) = (cps->neg² cps:kv)`。
- 认：`let` 与 `anf:let` 并排，分别是 `∘` 与 `∘𝒦` 的另一种写法；拿掉 `neg²:id` 的等式；两条运算律的绑定形状。
- 造：宏 `anf:let*-values`、`anf:begin`、`anf:let*`、`anf:if`、`anf:let/cc`；解释器 `anf:eval`。
- 名字：`kk3`、`cps:mul3`、`cps->neg²`、`neg²`、`neg²:id`、`anf:` 系列、`anf:eval`。宏保留 `(∘𝒦 cps:kv neg²:id)` 的形状。
- 练习：拿掉 `neg²:id` 的前提；推出四条运算律等式。
- 未定：`cps->neg²` 起名（Claude 倾向起）。
- 要试写才能判断：`neg` 用在 𝒰 箭头上，为什么结果算 𝒟 的箭头，要到第 7 节才解释；这段悬着是否难受。

## 6. 嵌入语言

- 造：用 `cps` 提升宿主函数；嵌入语言版 `mul`（`anf:let/cc` 逃逸，回指 3.2）；阴阳谜题与 `cps:label`。

### 6.1 计算的位置

- 认：每个绑定处有一个具体的延续；相邻两处只差 `(neg f)`；构造从 `a->⊥` 向内，运行时值向外。
- 名字：计算位置。

## 7. 否定翻译

由原来的「落回 𝒟」「否定翻译」两节改写合并，挪到程序写完之后。

- 问题：回看整段程序，用到的 `neg`、`flip`、`∘𝒦`、`cps:call/cc`、`cps->neg²` 和宏全是纯 λ。
- 造：把宿主拆成 𝒞 与 𝒟，说清两者类型别名相同，区别在允许哪些宿主程序（`display` 的口径统一）；`inj`。
- 认：𝒰 箭头读回宿主时两端对调；`←`、`⨾`，`∘𝒰 = ⨾`；`neg` 的 `case→` 第二行。这一段只回答：为什么 `cps->neg²` 造出的是 𝒟 里两个 $¬¬$ 之间的箭头。
- 认：两个经典出口与它们的构造性替身并排，逆否的构造性替身只作回看；纯性前提在 `neg` 第二种读法与 `neg²` 两处一起限定。
- 造：四世界表（「逻辑」栏改名「成立的定律」）与四世界图（𝒟 在顶，两种出口在底，保留 𝒞）。
- 认：命名**否定翻译**，指整段程序的翻译；`neg²` 是它在纯函数上的类型层特例，签名 𝒟 → 𝒟。
- 名字：𝒟、`→𝒟`、`inj`、`←`、`⨾`、否定翻译。
- 练习：换成「从 $¬¬p → ¬¬q$ 拿回 $p → ¬¬q$」。
- 注意框：Kuroda 与 Kolmogorov 的变体（措辞待核）。
- 撤掉：「能不能直接落回 𝒟」作为动机；「这是全部经典能力的来源」。
- 未定：本节放在 6.1 之后（Claude 倾向），还是之前。

## 8. 结论

- 回看：同样的 `let*`，背后的复合从 `∘` 换成 `∘𝒦`。𝒟 的口径同步。
